Danube is an open-source messaging platform written in Rust. It gives you pub/sub, durable task queues and event streams in a single `danube` binary, with no external coordinator to run.

It is built for two kinds of users: developers wiring services together, and teams building AI agents that need to hand work to each other safely.

## See it work

```bash
danube up standalone                                    # one node, ready on :6650
danube topic create /default/tasks --intent task_queue  # durable queue with retries and a DLQ
danube consume /default/tasks -s workers                # start a worker
danube produce /default/tasks -m 'resize image 42'      # hand it a job (second terminal)
```

Producers publish to **topics**. Consumers read through named **subscriptions**. The **intent** tells Danube how careful to be with each topic.

## What makes it different

<CardGrid>
	<Card title="One binary, every role" icon="setting">
		`danube up standalone|cluster|edge` starts a node. The same binary is your CLI, MCP server and console backend.

	<Card title="No coordinator, no YAML" icon="puzzle">
		Cluster metadata lives in embedded Raft. Cluster settings change live with `danube cluster ...` or `danube apply`, never in a config file.
	</Card>
	<Card title="Intents instead of knobs" icon="star">
		Four intents cover most workloads, from in-memory token streams to fsync'd audit logs.

	<Card title="Rust all the way down" icon="rocket">
		Built on Tokio. No JVM, no GC pauses, memory measured in megabytes.
	</Card>

## What you get

- **Messaging**: partitioned topics, four subscription types (Exclusive, Shared, Failover, Key-Shared), acks, NACKs, retries and dead-letter queues.
- **Agent building blocks**: lease extension, progress checkpoints, task-tree cancellation and request/reply in the Rust client.
- **Replay and debugging**: zero-copy topic branching, subscription seek, non-destructive peek and DLQ replay.
- **Storage**: local WAL plus tiered segments on S3, GCS, Azure Blob or a shared filesystem, with optional Iceberg export.
- **Schema registry**: JSON Schema, Avro and Protobuf with compatibility checks, built into the broker.
- **Security**: TLS, mTLS, auto-generated TLS, JWT and role-based access control.
- **Operations for agents**: `danube mcp` exposes admin tools and guided prompts to any MCP client.
- **Edge**: an MQTT gateway that buffers locally and replicates to your cluster.

Client libraries are available for Rust, Go, Java and Python. See [Client libraries](/client-libraries/overview/).
