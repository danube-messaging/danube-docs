Danube is an open-source, AI-native messaging and streaming platform built in Rust for teams that need reliable pub/sub, task queuing, and event streaming without operational overhead. Built on [Tokio](https://tokio.rs/) and [openraft](https://github.com/databendlabs/openraft), cluster metadata and shared configuration replicate through embedded Raft consensus—so there are no external coordinators or static broker YAML files to deploy or manage.

Producers publish to **topics**, and consumers receive messages via named **subscriptions**. Create topics with high-level **Stream Intents** (`realtime`, `event_stream`, `task_queue`, `audit_log`) or configure explicit `NonReliable` and `Reliable` dispatch per topic.

## Design Principles

<CardGrid>
	<Card title="Zero Dependencies & Zero YAML" icon="puzzle">
		Cluster metadata and `/cluster/config/*` policies live inside an embedded Raft engine (`openraft` + `redb`). Client gRPC, Schema Registry, and Admin gRPC multiplex onto a single port (`6650`), so one binary starts a cluster with CLI flags alone.
	</Card>
	<Card title="One Binary, All Modes" icon="setting">
		Run as **Standalone** for dev, **Cluster** for production (`--node-role broker|lakehouse|all`), **Edge** for MQTT ingestion, **CLI/UI** (`danube ctl`), or **MCP** (`danube mcp`), all from the single `danube` binary.
	</Card>
	<Card title="Rust-Native" icon="rocket">
		Built on Tokio for async I/O. No JVM, no GC pauses, no warm-up time. Predictable latency with a memory footprint measured in megabytes.
	</Card>
	<Card title="Built for AI Agents" icon="star">
		First-class agentic primitives (`extend_lease`, `report_progress`, `cancel_task_tree`, `request_reply`), zero-copy topic branching, schema inference, and a 71-tool MCP server backed by built-in telemetry and log ring buffers.
	</Card>
</CardGrid>

## Core Capabilities

- **Workload Intents & Message Delivery**: Four canonical `--intent` profiles (`realtime`, `event_stream`, `task_queue`, `audit_log`), partitioned and non-partitioned topics, `NonReliable` / `Reliable` dispatch, NACKs, exponential retry backoff, and dead-letter queues.
- **Agent Runtime Primitives**: Visibility lease extension (`extend_lease`), resumable progress checkpoints (`report_progress` / `x-danube-checkpoint-b64`), tree cancellation (`cancel_task_tree`), and correlated `request_reply` RPC.
- **Time-Travel & Topic Branching**: Zero-copy `topics branch` at any offset or nanosecond timestamp, subscription `seek`, `peek`, `replay-dlq`, and live `infer-schema`.
- **Subscriptions**: Exclusive, Shared, Failover, and Key-Shared with per-key ordering via consistent hashing and glob-pattern key filtering.
- **Persistence & Lakehouse**: Local WAL for fast writes, durable segments on shared filesystems or object stores (S3, GCS, Azure), plus optional Apache Iceberg lakehouse export.
- **Schema Registry**: Built-in schema management with JSON Schema, Avro, and Protobuf. Version control with backward, forward, and full compatibility enforcement.
- **Security**: Zero-trust `--auth-mode auto-tls`, manual TLS/mTLS encryption, JWT and API-key authentication, and fine-grained RBAC with default-deny semantics.
- **AI Control Plane (`danube mcp`)**: Native Model Context Protocol server with **71 tools**, **4 guided workflows** (including `explain_consumer_stall`), GitOps `apply_desired_state`, and built-in 1-hour gRPC telemetry/log ring buffers—no Prometheus required.
- **Danube Connect**: Plug-and-play connector ecosystem with source connectors (MQTT, HTTP webhooks, databases) and sink connectors (Delta Lake, Qdrant, SurrealDB).
