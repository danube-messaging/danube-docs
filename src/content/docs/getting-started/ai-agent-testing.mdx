## Run a test scenario with agent skills

<Steps>

1. **Clone the skills repo**

   ```bash
   git clone https://github.com/danube-messaging/danube-agent-skills.git
   cd danube-agent-skills
   ```

2. **Open it in your assistant**

   Claude Code, Antigravity, Cursor, Codex or any assistant that reads `SKILL.md` files.

3. **Ask for what you want to test**

   > *"Test task_queue delivery with NACK redelivery and dead-letter queue replay."*

   The assistant picks the matching skill, confirms how to run Danube (binary, source, Docker Compose or Kubernetes), runs the scenario in an isolated workspace and summarizes the results.

</Steps>

## Debug a live cluster with MCP

Already running Danube? Connect your assistant to it:

```bash
danube mcp                                # stdio, broker at http://127.0.0.1:6650
danube mcp --endpoint http://broker:6650  # any other broker
```

The assistant can now check broker health, list topics and subscriptions, peek messages, explain a stalled consumer, branch topics and preview changes with dry runs. Destructive tools require explicit confirmation. Setup snippets for each IDE are in the [MCP server guide](/admin/mcp/).

## Prompts to try

- *"Start a standalone node and compare `task_queue` and `realtime` behavior when a consumer disconnects."*
- *"Branch `/default/orders` at offset 100 and replay it to a fresh consumer."*
- *"Why is the `workers` subscription on `/default/orders` not making progress?"*
- *"Bring up a three-node cluster with `--auth auto-tls` and check that RBAC blocks an unauthorized producer."*
- *"Test edge MQTT ingest with store-and-forward while the cloud cluster is down."*

## What you can test

- **Messaging and intents**: all four intents, partitions and subscription types.
- **Agent primitives**: lease extension, progress checkpoints, task-tree cancellation, request/reply.
- **Reliability**: NACKs, retry backoff, DLQ routing and `danube topic dlq replay`.
- **Schemas**: JSON Schema, Avro and Protobuf, compatibility checks, `danube topic schema infer`.
- **Replay**: `danube topic branch`, subscription seek and peek.
- **Operations**: scaling with `--join` and `danube cluster node ...`, leader failover, `danube apply`, tiered storage.
- **Security**: auto-TLS, TLS and mTLS, JWT, roles and bindings.
- **Edge**: MQTT ingest with local buffering and replication.

<Aside type="tip">
Each scenario runs in its own workspace directory, so runs never leak data into each other.
</Aside>
