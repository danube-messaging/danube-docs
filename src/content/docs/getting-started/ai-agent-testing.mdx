Danube provides two complementary ways to test, explore, and operate clusters with AI coding assistants (Claude Code, Antigravity, Cursor, Codex, Windsurf):

1. **[Danube Agent Skills (`danube-agent-skills`)](https://github.com/danube-messaging/danube-agent-skills)**: Automated end-to-end test workflows driven from natural-language prompts.
2. **Built-in AI Control Plane (`danube mcp`)**: A native Model Context Protocol server embedded directly in the `danube` binary with **71 tools**, **4 guided diagnostic workflows**, and zero-dependency telemetry/log ring buffers.

## Automated Testing with `danube-agent-skills`

The [Danube Agent Skills](https://github.com/danube-messaging/danube-agent-skills) repository lets an AI assistant bootstrap clusters, install SDK dependencies, run test scenarios, and verify pass/fail results automatically.

### How It Works

Open the repository in an AI assistant that supports `SKILL.md` workflows, describe what you want to test in plain English, and the assistant handles the lifecycle:

- Installs or builds the single `danube` binary
- Launches standalone, zero-YAML cluster (`danube up`), or zero-YAML edge (`danube up --mode edge`) topologies with single-port multiplexing on `6650`
- Configures dynamic Raft policies (`danube ctl cluster ...` or `danube ctl apply`) and `--intent` topics (`realtime`, `event_stream`, `task_queue`, `audit_log`)
- Runs client/SDK tests and inspects results, reporting pass/fail outcomes

Each run uses an isolated workspace directory so nothing leaks between scenarios.

### Quick Start

<Steps>
1. **Clone the repository**

   ```bash title="Terminal"
   git clone https://github.com/danube-messaging/danube-agent-skills.git
   cd danube-agent-skills
   ```

2. **Open in your AI IDE**

   Open the `danube-agent-skills` folder in Claude Code, Antigravity, Cursor, Codex, or another `SKILL.md`-capable assistant.

3. **Tell the AI what to test**

   Type a prompt such as:

   > *"Test reliable task_queue delivery with NACK redelivery and dead-letter queue replay"*

   The assistant reads the relevant skill instructions, confirms your setup method, executes the scenario, and summarizes the results.
</Steps>

## Live Cluster Debugging & Diagnostics (`danube mcp`)

Whenever you already have a running Danube cluster (`standalone`, `cluster`, or Docker Compose), connect your AI assistant directly to **`danube mcp`** (or the HTTP endpoint at `/mcp` via `danube ctl serve --mode all`):

```bash
# Start stdio MCP against your local cluster (port 6650)
danube mcp --broker-endpoint http://127.0.0.1:6650
```

Because brokers maintain built-in **1-hour telemetry ring buffers** (`GetMetricsSnapshot`) and **5,000-entry structured log ring buffers** (`GetBrokerLogs`) directly in memory over gRPC, AI agents can run diagnostics—such as **`explain_consumer_stall`**, topic lag inspection, `topics peek`, zero-copy `topics branch`, `infer-schema`, and `apply_desired_state` (`dry_run` preview + `confirm_destructive` guardrails)—without deploying Prometheus or log-scraping containers.

## Example Prompts

- *"Start a standalone `danube` broker and test `task_queue` vs `realtime` intent behavior"*
- *"Run the `explain_consumer_stall` MCP workflow on `/agents/tasks` and inspect recent broker logs"*
- *"Set up a zero-YAML 3-node cluster with `--auth-mode auto-tls` and verify RBAC enforcement"*
- *"Test agent runtime primitives: `extend_lease`, `report_progress` checkpoints, and `cancel_task_tree`"*
- *"Branch `/agents/events` at offset 100 and replay historical events to an isolated consumer"*
- *"Test zero-YAML edge MQTT ingestion (`--mode edge`) with store-and-forward replay"*

## Setup Methods
