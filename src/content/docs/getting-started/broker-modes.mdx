Danube runs as a single binary (`danube`) using `danube up --mode <mode>` in one of three modes. All modes start **zero-YAML**—no `danube_broker.yml` or `edge.yaml` file is required—and multiplex Client gRPC, Schema Registry, and Admin gRPC onto port `6650` by default.

## At a Glance

<CardGrid>
	<Card title="Standalone" icon="laptop">
		Single broker, zero configuration. Ideal for development, CI, and single-server deployments.

		- **Brokers**: 1
		- **Config**: CLI flags only (zero YAML)
		- **Raft**: single-node, auto-init
		- **Port**: `127.0.0.1:6650` (Client + Schema + Admin multiplexed)
	</Card>
	<Card title="Cluster" icon="setting">
		Multi-broker with Raft consensus, dynamic `/cluster/config/*` replication, and load-based rebalancing. Recommended for production.

		- **Brokers**: 3+ (recommended)
		- **Config**: Zero-YAML node flags + dynamic Raft state (`danube ctl cluster` / `danube ctl apply`)
		- **Node Roles**: `broker`, `lakehouse`, or `all` (`--node-role`)
		- **Clients**: Danube gRPC (`6650`)
	</Card>
	<Card title="Edge" icon="open-book">
		Lightweight zero-YAML MQTT gateway for IoT ingestion with local WAL buffering and cluster replication.

		- **Config**: Zero-YAML (`--edge-name`, `--cloud-endpoint`)

	</Card>

## Standalone Mode

The fastest way to get started: a single broker with zero config files and zero external dependencies.

```bash title="Start standalone broker"
danube up --mode standalone --data-dir ./danube-data
```

Default bind configuration:

| Setting | Default |
|---------|---------|
| Broker / Admin / Schema address | `127.0.0.1:6650` (multiplexed) |
| Raft address | `127.0.0.1:7650` |
| Data directory | `./danube-data` |
| Storage mode | Local WAL |
| Authentication | `none` |

Override any default with CLI flags (for example, adding a dedicated `--admin-addr` if you want firewall separation, or isolating the WAL on NVMe via `--wal-dir`):

```bash title="Override defaults"
danube up --mode standalone \
  --data-dir ./danube-data \
  --wal-dir ./danube-wal \
  --broker-addr 0.0.0.0:6650 \
  --admin-addr 0.0.0.0:50051
```

:::note
Standalone mode supports the exact same client SDK APIs, `--intent` profiles, schema registry, and MCP tools as cluster mode, without multi-broker orchestration.
:::

Data persists across restarts in `--data-dir` (and `--wal-dir` if specified). To start fresh, remove those directories and restart the broker.

## Cluster Mode

The recommended mode for production. Multiple brokers form a Raft consensus group, replicate cluster configuration under `/cluster/config/*`, and distribute topics across nodes.

### Requirements

- Zero YAML files required (`danube_broker.yml` is gone)
- At least 3 brokers for Raft quorum (recommended)
- Network connectivity between broker gRPC (`6650`) and Raft (`7650`) ports

### Starting a Zero-YAML Cluster

Start each node with its local addresses, `--data-dir`, and `--seed-nodes`:

```bash title="Broker 1"
danube up --mode cluster \
  --broker-addr 0.0.0.0:6650 \
  --raft-addr 0.0.0.0:7650 \
  --data-dir ./data1 \
  --seed-nodes "127.0.0.1:7650,127.0.0.1:7651,127.0.0.1:7652"
```

```bash title="Broker 2"
danube up --mode cluster \
  --broker-addr 0.0.0.0:6651 \
  --raft-addr 0.0.0.0:7651 \
  --data-dir ./data2 \
  --seed-nodes "127.0.0.1:7650,127.0.0.1:7651,127.0.0.1:7652"
```

```bash title="Broker 3"
danube up --mode cluster \
  --broker-addr 0.0.0.0:6652 \
  --raft-addr 0.0.0.0:7652 \
  --data-dir ./data3 \
  --seed-nodes "127.0.0.1:7650,127.0.0.1:7651,127.0.0.1:7652"
```

Once the cluster boots, configure shared storage, write buffers, WAL retention, load management, and topics dynamically via `danube ctl cluster ...` or declaratively via `danube ctl apply -f desired_state.yaml`. See [Configuration Workflow](/getting-started/configuration-workflow/).

### Cluster Features

- **Leader election & dynamic config**: Embedded Raft (`openraft` + `redb`) manages cluster state and `/cluster/config/*` policies across all brokers.
- **Node roles (`--node-role`)**: Run general-purpose `all` nodes or dedicate specialized `broker` and `lakehouse` nodes.
- **Security (`--auth-mode`)**: Enable zero-trust cluster certificates with `--auth-mode auto-tls`, bring custom certs with `--auth-mode tls`, or run unencrypted with `--auth-mode none`.
- **Load manager**: Assigns and rebalances topics using `fair`, `balanced`, or `weighted_load` strategies.
- **Broker scaling**: Add nodes dynamically with `--join` or `danube ctl cluster add-node --node-addr <addr>`.

:::tip
For containerized or orchestrator deployments, see [Docker Compose](/getting-started/docker-compose/) or [Kubernetes](/getting-started/kubernetes/).
:::

## Edge Mode

Edge mode turns `danube` into a lightweight zero-YAML MQTT gateway that ingests IoT device messages locally, buffers them safely to a WAL during WAN outages, and replicates them over gRPC to your central Danube cluster.

### How It Works

<Steps>
1. Devices publish via standard MQTT (v3.1.1 / v5.0) on `--mqtt-addr` (default `0.0.0.0:1883`)

2. The zero-YAML edge broker routes all MQTT topics (`#`) to `/{edge_name}/ingest` (for example, `/edge1/ingest`)

3. Messages are batched and written to a durable local WAL in `--data-dir`

4. A background replicator tails the WAL and streams batches to `--cloud-endpoint` over gRPC

5. If the central cluster is unreachable, messages accumulate locally and resume from the last checkpoint when connectivity returns
</Steps>

### Starting a Zero-YAML Edge Broker

No `edge.yaml` file is needed—specify `--mode edge`, `--edge-name`, and `--cloud-endpoint`:

```bash title="Start edge broker"
danube up --mode edge \
  --edge-name edge1 \
  --cloud-endpoint http://cluster:6650 \
  --mqtt-addr 0.0.0.0:1883 \
  --data-dir ./edge-data
```

Default edge settings (`EdgeConfig`):

| Setting | Default |
|---------|---------|
| MQTT listener (`--mqtt-addr`) | `0.0.0.0:1883` |
| Catch-all topic route | `# -> /{edge_name}/ingest` |
| Heartbeat interval | `30000 ms` |
| Max payload size | `256 KiB` (`262144` bytes) |
| Max concurrent MQTT connections | `10000` |

### Testing with an MQTT Client

```bash title="Publish via MQTT"
mosquitto_pub -h 127.0.0.1 -p 1883 \
  -t "device/sensor-1/telemetry" \
  -m '{"temperature": 25.5, "device_id": "sensor-1"}'
```

Messages flow through the edge WAL to `/edge1/ingest` on your central cluster, where standard consumers or `danube ctl consume -t /edge1/ingest --subscription edge-reader` can read them. For custom edge overrides or advanced topologies, pass `--recovery-config <path>` and see the [Edge & IoT Overview](/edge/overview/).

## CLI Reference (`danube up`)

```text title="danube up options"
danube up [OPTIONS]

Common options:
  --mode <mode>              cluster (default), standalone, or edge
  --broker-addr <addr>       Client, Schema & default Admin gRPC address (default: 127.0.0.1:6650)
  --admin-addr <addr>        Optional separate Admin gRPC listen address
  --advertised-addr <addr>   Advertised gRPC address for cluster discovery
  --connect-url <addr>       Proxy or external connect URL advertised to clients
  --raft-addr <addr>         Raft transport address (default port: 7650)
  --data-dir <path>          Base data directory (default: ./danube-data)
  --wal-dir <path>           Optional separate directory for WAL storage
  --prom-exporter <addr>     Prometheus metrics exporter endpoint
  --recovery-config <path>   Break-glass recovery / override YAML file

Cluster & security options:
  --seed-nodes <addrs>       Comma-separated Raft peer addresses
  --join                     Join an existing Raft cluster
  --node-role <role>         all (default), broker, or lakehouse
  --auth-mode <mode>         none, tls, or auto-tls
  --tls-cert <path>          TLS certificate path
  --tls-key <path>           TLS private key path
  --ca-cert <path>           CA certificate path
  --jwt-secret <secret>      JWT signing secret
  --super-admins <principals> Comma-separated RBAC super-admin principals

Edge options (--mode edge):
  --edge-name <name>         Edge node name & target namespace (default: $HOSTNAME / edge-node)
  --cloud-endpoint <url>     Upstream Danube cluster gRPC URL (required unless --recovery-config)
  --mqtt-addr <addr>         MQTT listen address (default: 0.0.0.0:1883)
  --edge-token <token>       Auth token override
```

For full details on every flag and Raft setting, see [Broker Configuration & CLI Flags](/reference/broker-configuration/).
