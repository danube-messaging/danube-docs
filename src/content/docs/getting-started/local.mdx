Run a Danube broker directly on your machine. No Docker, no Kubernetes, no YAML configuration files—just the single `danube` binary.

## Download

Download the latest `danube` binary from the [releases page](https://github.com/danube-messaging/danube/releases) (it bundles the broker, CLI, admin, and MCP server into one executable).

## Single-Node Quick Start

Start a broker locally with zero config files:

<Steps>
1. **Start the broker**

   ```bash title="Terminal 1"
   danube up --mode standalone --data-dir ./danube-data
   ```

   Defaults configured automatically:

   | Setting | Value |
   |---------|-------|
   | Broker / Admin / Schema address | `127.0.0.1:6650` (single-port multiplexed) |
   | Raft address | `127.0.0.1:7650` |
   | Raft & segment data | `./danube-data` |
   | WAL directory | Inside `--data-dir` (or custom `--wal-dir`) |
   | Authentication | `none` |
   | Storage mode | Local |

2. **Produce messages**

   ```bash title="Terminal 2"
   danube ctl produce \
     -s http://127.0.0.1:6650 \
     -t /default/demo_topic \
     -c 10 \
     -m "Hello, Danube!"
   ```

3. **Consume messages**

   ```bash title="Terminal 3"
   danube ctl consume \
     -s http://127.0.0.1:6650 \
     -t /default/demo_topic \
     --subscription my_subscription
   ```
</Steps>

Data persists across restarts in `./danube-data`. To start fresh, remove the data directory and re-run.

## Multi-Broker Cluster (Local)

You can run a multi-broker Raft cluster directly on localhost with zero YAML files—just give each broker unique ports and `--data-dir`, and list `--seed-nodes`:

```bash title="Broker 1"
danube up --mode cluster \
  --broker-addr 127.0.0.1:6650 \
  --raft-addr 127.0.0.1:7650 \
  --data-dir ./data1 \
  --seed-nodes "127.0.0.1:7650,127.0.0.1:7651" &
```

```bash title="Broker 2"
danube up --mode cluster \
  --broker-addr 127.0.0.1:6651 \
  --raft-addr 127.0.0.1:7651 \
  --data-dir ./data2 \
  --seed-nodes "127.0.0.1:7650,127.0.0.1:7651" &
```

:::note[Optional Separate Admin Port]
Admin gRPC multiplexes onto `--broker-addr` (`6650` / `6651`) by default. Pass `--admin-addr 0.0.0.0:50051` (with `--endpoint http://127.0.0.1:50051` on `danube ctl`) whenever you want Admin gRPC isolated on a separate port.
:::

Once running, manage storage, WAL retention, load balancing, and topics dynamically via `danube ctl`—see [Configuration Workflow](/getting-started/configuration-workflow/).

## Cleanup

```bash
# Stop the broker(s)
pkill -x danube

# Remove data (for a fresh start)
rm -rf ./danube-data ./data1 ./data2

# Verify
ps aux | grep danube
```
