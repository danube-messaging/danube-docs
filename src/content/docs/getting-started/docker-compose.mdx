Danube ships a consolidated Docker Compose setup in `danube/docker/` that starts a **zero-YAML 3-broker Raft cluster** using the single `/usr/local/bin/danube` binary—no mounted `danube_broker.yml` files, no ZooKeeper/ETCD, and no separate CLI or admin containers required.

## Prerequisites

- Docker Engine 20.10+
- Docker Compose 2.0+
- At least 2GB RAM

---

## Start the 3-Node Cluster

<Steps>
1. **Clone the repository and navigate to `danube/docker`**

   ```bash
   git clone https://github.com/danube-messaging/danube.git
   cd danube/docker
   ```

2. **Build and start the 3 brokers**

   ```bash
   docker compose up -d --build
   ```

3. **Verify all brokers are healthy**

   ```bash
   docker compose ps
   ```

   All three nodes (`broker1`, `broker2`, `broker3`) form an embedded Raft cluster using `--seed-nodes` and expose multiplexed Client gRPC, Schema Registry, and Admin gRPC on ports `6650`-`6652`, plus Prometheus exporters on `9040`-`9042`:

   | Container | Service | gRPC Port (Client + Schema + Admin) | Prometheus Metrics |
   |-----------|---------|-------------------------------------|--------------------|
   | `danube-broker1` | `broker1` | `localhost:6650` | `localhost:9040/metrics` |
   | `danube-broker2` | `broker2` | `localhost:6651` | `localhost:9041/metrics` |
   | `danube-broker3` | `broker3` | `localhost:6652` | `localhost:9042/metrics` |
</Steps>

## Run Standalone with `docker run`

If you only need a single container without cloning the repository, pull `ghcr.io/danube-messaging/danube:latest`:

```bash title="Standalone container"
docker run -d --name danube \
  -p 6650:6650 -p 9040:9040 \
  ghcr.io/danube-messaging/danube:latest \
  up --mode standalone --data-dir /danube-data \
  --broker-addr 0.0.0.0:6650 --prom-exporter 0.0.0.0:9040
```

## Interact Using `danube ctl`

Because `danube` bundles the CLI, Admin, and MCP server inside the same container image, run `danube ctl` directly against `danube-broker1` via `docker exec` (or from your host pointing `--endpoint` / `DANUBE_ADMIN_ENDPOINT` at `http://127.0.0.1:6650`).

### Produce & Consume Messages

```bash title="Produce messages"
docker exec danube-broker1 danube ctl produce \
  -s http://127.0.0.1:6650 \
  -t /default/test \
  -c 20 \
  -m "Hello Danube!"
```

```bash title="Consume messages"
docker exec -it danube-broker1 danube ctl consume \
  -s http://127.0.0.1:6650 \
  -t /default/test \
  --subscription my-sub
```

### Intent-Driven Topics, Branching & GitOps Apply

Provision topics with canonical workload intents (`realtime`, `event_stream`, `task_queue`, `audit_log`), create zero-copy branches for replay, and apply declarative cluster state directly over stdin:

```bash title="Create intent-driven topics & branch"
# Create a durable task queue topic (5 retries, fsync_batch, DLQ -> /default/tasks-dlq)
docker exec danube-broker1 danube ctl topics create /default/tasks \
  --intent task_queue --partitions 4

# Non-destructively peek at the first 5 messages
docker exec danube-broker1 danube ctl topics peek /default/tasks --start-offset 0 --count 5

# Create a zero-copy counterfactual branch at offset 10
docker exec danube-broker1 danube ctl topics branch /default/tasks /default/tasks-replay --at-offset 10
```

```bash title="Declarative GitOps apply over stdin"
docker exec -i danube-broker1 danube ctl apply -f - << 'EOF'
namespaces:
  - /agents
topics:
  - name: /agents/events
    intent: event_stream
    partitions: 3
  - name: /agents/tool-audit
    intent: audit_log
EOF
```

### Cluster Administration

```bash title="Inspect cluster & Raft status"
docker exec danube-broker1 danube ctl cluster status
docker exec danube-broker1 danube ctl brokers list
docker exec danube-broker1 danube ctl topics list --namespace default
```

## Configuration Overrides & Security

- **Dynamic Cluster Config**: Manage tiered storage (`cluster storage`), write buffer (`cluster write-buffer`), WAL retention (`cluster wal`), and load rebalancing (`cluster load-manager`) directly via `danube ctl cluster ...`—settings replicate automatically over Raft without editing YAML files. See [Configuration Workflow](/getting-started/configuration-workflow/).
- **Single-Port vs. Isolated Admin Port**: Admin gRPC shares port `6650` by default. To bind Admin gRPC to a separate port for network isolation, pass `--admin-addr 0.0.0.0:50051` to `danube up` in your Compose command.
- **Zero-Trust Security (`--auth-mode`)**: Add `--auth-mode auto-tls` (or `--auth-mode tls` with mounted certs) to `danube up` in `docker-compose.yml` to enable encrypted client/peer communication.
- **Break-Glass Recovery (`--recovery-config`)**: Pass `--recovery-config /path/to/recovery.yaml` alongside `danube ctl cluster export-config` snapshots if you ever need node-local overrides before Raft convergence.

## Troubleshooting & Reset

- **Port conflicts**: Ensure host ports `6650`-`6652` and `9040`-`9042` are free.
- **Follow logs**: `docker compose logs -f broker1`
- **Built-in telemetry without Prometheus**: Brokers keep 1 hour of metrics (`GetMetricsSnapshot`) and 5,000 log entries (`GetBrokerLogs`) in memory, queryable directly via `danube mcp`.
- **Prometheus metrics endpoint**: `curl http://localhost:9040/metrics`

```bash title="Full reset"
docker compose down -v
docker compose up -d --build
```

<Aside type="caution">
  This Docker Compose setup is intended for local development and integration testing. For production deployments, enable TLS/RBAC (`--auth-mode auto-tls` or `tls`), configure S3/GCS/Azure tiered storage via `danube ctl cluster storage object-store`, and deploy on [Kubernetes](/getting-started/kubernetes/).
</Aside>
