Get a real three-node Raft cluster on your laptop with one command. The Compose file in the Danube repository builds the image and starts three brokers. No config files are mounted.

```bash
cd danube/docker && docker compose up -d --build
```

## Prerequisites

- Docker Engine 20.10+
- Docker Compose 2.0+

## Start the cluster

<Steps>
1. **Clone the repository.**

   ```bash
   git clone https://github.com/danube-messaging/danube.git
   cd danube/docker
   ```

2. **Build the image and start three brokers.**

   ```bash
   docker compose up -d --build
   ```

3. **Check that all three containers run.**

   ```bash
   docker compose ps
   ```
</Steps>

Each broker is reachable from your host:

- **`danube-broker1`**: gRPC on `localhost:6650`, metrics on `localhost:9040/metrics`
- **`danube-broker2`**: gRPC on `localhost:6651`, metrics on `localhost:9041/metrics`
- **`danube-broker3`**: gRPC on `localhost:6652`, metrics on `localhost:9042/metrics`

Each gRPC port serves clients, the schema registry and admin commands.

## How the brokers start

Every service runs the same command, changing only its advertised name:

```yaml title="docker/docker-compose.yml (broker1)"
command:
  [
    "up", "cluster",
    "--data-dir", "/danube-data",
    "--listen", "0.0.0.0:6650",
    "--raft-port", "7650",
    "--metrics-listen", "0.0.0.0:9040",
    "--advertised-addr", "broker1:6650",
    "--seed-nodes", "broker1:7650,broker2:7650,broker3:7650",
  ]
```

- **`--seed-nodes`**: the three brokers find each other and the lowest node id bootstraps the cluster.
- **`--advertised-addr`**: the name other brokers and clients use. The Raft address is derived from it (`broker1:7650`).
- **`/danube-data`**: a named volume per broker, so data survives `docker compose restart`.

## Produce and consume

Every container ships the `danube` binary, so you don't need a separate CLI container. Commands default to the broker inside the container.

```bash title="Terminal 1: consume"
docker exec -it danube-broker1 danube consume /default/test -s my-sub
```

```bash title="Terminal 2: produce"
docker exec danube-broker1 danube produce /default/test \
  --count 100 \
  --message "Hello Danube!"
```

## Create topics and apply a manifest

```bash
# A durable task queue (5 retries, DLQ at /default/agent-tasks-dlq)
docker exec danube-broker1 danube topic create /default/agent-tasks --intent task_queue

# Fork the topic into a new one for replay
docker exec danube-broker1 danube topic branch /default/agent-tasks /default/agent-tasks-replay
```

Pipe a manifest from your host through stdin:

```bash
docker exec -i danube-broker1 danube apply -f - <<'EOF'
namespaces:
  - agents
topics:
  - name: /agents/events
    intent: event_stream
    partitions: 3
  - name: /agents/tool-audit
    intent: audit_log
EOF
```

## Inspect the cluster

```bash
docker exec danube-broker1 danube cluster status
docker exec danube-broker1 danube broker list
docker exec danube-broker1 danube topic list --namespace default
```

Cluster-wide settings (storage, write buffer, WAL, load manager) are changed live with `danube cluster ...`. See [Configure Cluster & Topics](/getting-started/configuration-workflow/).

## Run a single standalone container

Build the image once and run one node:

```bash
docker build -t danube:local -f Dockerfile .
docker run --rm -p 6650:6650 -p 9040:9040 \
  danube:local up standalone \
  --data-dir /danube-data \
  --listen 0.0.0.0:6650 \
  --metrics-listen 0.0.0.0:9040
```

Run the `docker build` from the repository root. Released images are also published as `ghcr.io/danube-messaging/danube`.

## Customize the containers

Add flags to the `command` list of each service:

- **TLS**: `--auth auto-tls`, or `--auth tls` with `--tls-cert`, `--tls-key` and `--ca-cert` (plus optional `--jwt-secret` and `--super-admin`).
- **Separate admin port**: `--admin-listen 0.0.0.0:50051` to firewall admin gRPC away from `6650`.
- **Check before you start**: append `--dry-run` to print the resolved configuration.
- **Break-glass recovery**: mount a file exported with `danube cluster export-config` and pass `--recovery-config /path/to/recovery.yaml`.

## Troubleshoot and reset

```bash
docker compose logs -f broker1          # follow one broker
curl http://localhost:9040/metrics      # Prometheus metrics
docker compose down -v                  # stop and delete all data
```

If a container exits right away, check that host ports `6650`-`6652` and `9040`-`9042` are free.

<Aside type="caution">
  This setup is for development and testing. For production, enable TLS, configure tiered storage with `danube cluster storage object-store` and run on [Kubernetes](/getting-started/kubernetes/).
</Aside>
