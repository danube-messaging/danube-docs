title: Quickstart
description: Run Danube, create a topic, send and read messages, then hand the cluster to an AI agent. Five minutes.
---

import { Steps, Tabs, TabItem, Aside, LinkCard, CardGrid } from '@astrojs/starlight/components';

Five minutes from nothing to a working broker, a durable topic and your first messages. At the end you connect an AI agent to it.

<Steps>

1. **Get the `danube` binary**

   <Tabs>
   <TabItem label="Download">
   Grab the latest build for your platform from the [releases page](https://github.com/danube-messaging/danube/releases) and put `danube` on your `PATH`.
   </TabItem>
   <TabItem label="Build from source">
   ```bash
   git clone https://github.com/danube-messaging/danube.git
   cd danube
   cargo build --release        # binary at target/release/danube
   ```
   </TabItem>
   <TabItem label="Docker">
   ```bash
   docker run -d --name danube -p 6650:6650 \
     ghcr.io/danube-messaging/danube:latest \
     up standalone --data-dir /danube-data \
     --listen 0.0.0.0:6650 --advertised-addr 127.0.0.1:6650
   ```
   Skip step 2. Run the client commands below on your host with a local `danube`, or prefix them with `docker exec danube`.
   </TabItem>
   </Tabs>

2. **Start a node**

   ```bash title="Terminal 1"
   danube up standalone
   ```

   Danube listens on `127.0.0.1:6650` and stores data in `./danube-data`. Clients, schema registry and admin all share that one port.

3. **Create a topic with an intent**

   ```bash title="Terminal 2"
   danube topic create /default/orders --intent task_queue
   ```

   `task_queue` makes the topic durable, with 5 retries and a dead-letter queue at `/default/orders-dlq`. See [Stream intents](/concepts/stream-intents/) for the other three.

4. **Start a consumer**

   ```bash title="Terminal 3"
   danube consume /default/orders -s workers
   ```

   This creates the `workers` subscription and waits. A new subscription starts at the end of the topic, so start it before producing. Add `--limit 5 -o jsonl` for scripts.

5. **Produce messages**

   ```bash title="Terminal 2"
   danube produce /default/orders -m 'order #1' -c 5
   ```

   `-c 5` sends five messages and they show up in Terminal 3. The producer uses the topic's reliable delivery, so no extra flag is needed. Press Ctrl-C in Terminal 3 when done.

6. **Inspect the topic**

   ```bash
   danube topic describe /default/orders
   ```

   You see the topic's delivery settings, schema and the `workers` subscription.

7. **Connect an AI agent**

   ```bash
   danube mcp
   ```

   This runs an MCP server over stdio against your local node. Add it to Claude Code, Cursor or Antigravity and ask things like "which subscriptions are lagging?". See [Danube for AI agents](/ai-agents/overview/#connect-your-agent-with-mcp) for the config snippet.

</Steps>

<Aside type="tip">
Want a clean slate? Stop the node and delete `./danube-data`.
</Aside>
