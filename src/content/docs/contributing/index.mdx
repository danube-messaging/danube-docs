This page walks through the contribution workflow from fork to merged pull request. Danube is built in Rust with embedded Raft consensus, single-port multiplexing (`6650`), and zero-YAML defaults—no external dependencies like etcd or ZooKeeper are required.

---

## Prerequisites

| Tool | Version | Purpose |
|------|---------|---------|
| [Rust](https://www.rust-lang.org/tools/install) | Stable | Build the unified `danube` binary and workspace crates |
| [protobuf-compiler](https://grpc.io/docs/protoc-installation/) | 3.x+ | Generate gRPC code from `.proto` files |
| [Docker](https://docs.docker.com/get-docker/) | 20.10+ | Optional: containerized 3-broker cluster or Prometheus |
| [Docker Compose](https://docs.docker.com/compose/install/) | 2.0+ | Optional: consolidated `docker/docker-compose.yml` cluster |

## Fork and Clone

<Steps>
1. **Fork** the repository at [github.com/danube-messaging/danube](https://github.com/danube-messaging/danube)

2. **Clone** your fork:

   ```bash
   git clone https://github.com/<your-username>/danube.git
   cd danube
   ```

3. **Add upstream** (recommended for staying up to date):

   ```bash
   git remote add upstream https://github.com/danube-messaging/danube.git
   ```
</Steps>

## Build

Danube compiles into a **single unified binary** (`danube`) containing the broker (`danube up`), admin/messaging CLI & web UI (`danube ctl`), and MCP server (`danube mcp`):

```bash
# Release binary at ./target/release/danube
cargo build --release -p danube-broker

# Include Apache Iceberg lakehouse export support (add lakehouse-aws for S3)
cargo build --release -p danube-broker --features lakehouse
```

For faster incremental iteration during development:

```bash
cargo build -p danube-broker
```

Check the entire workspace (including optional lakehouse crates):

```bash
cargo check --workspace --features danube-broker/lakehouse
```

## Running a Local Cluster

You have two options for running a local 3-broker development cluster: **Makefile** (native, fastest for daily work) or **Docker Compose** (consolidated containerized setup in `docker/`).

### Option A: Makefile (Native)

The `Makefile` builds `./target/release/danube` and launches a zero-YAML 3-broker Raft cluster on localhost with single-port multiplexing (Client gRPC, Schema Registry, and Admin gRPC all served on each broker's primary port):

**Start the cluster:**

```bash
make brokers
```

| Broker | Multiplexed gRPC Port (Client + Schema + Admin) | Raft Port | Prometheus |
|--------|--------------------------------------------------|-----------|------------|
| Broker 0 | `6650` | `7650` | `9040` |
| Broker 1 | `6651` | `7651` | `9041` |
| Broker 2 | `6652` | `7652` | `9042` |

Logs are written to `temp/broker_<port>.log`.

**Useful targets:**

| Command | Description |
|---------|-------------|
| `make brokers` | Build and start 3 `danube up` brokers |
| `make brokers-stop` | Stop all brokers (keep Raft data for restart testing) |
| `make brokers-clean` | Stop all brokers and delete Raft/WAL data |
| `make broker-kill ID=0` | Kill a single broker by index (`0`, `1`, or `2`) |
| `make broker-start ID=0` | Start a single broker by index |
| `make cluster-status` | Show Raft cluster status via `danube ctl cluster status` |
| `make data-clean` | Remove all local Raft/data directories |
| `make admin` | Start the Admin UI (`danube ctl serve --mode ui`) on port `8080` |
| `make admin-clean` | Stop the Admin UI server |
| `make prom` | Start Prometheus on port `9090` (Docker) |
| `make prom-clean` | Stop Prometheus |

**Custom log levels:**

```bash
RUST_LOG=danube_broker=debug make brokers
```

### Option B: Docker Compose (Containerized)

The consolidated `docker/docker-compose.yml` builds `/usr/local/bin/danube` from `Dockerfile` and runs a zero-YAML 3-broker Raft cluster (`broker1`, `broker2`, `broker3`):

```bash
cd docker
docker compose up -d --build
```

| Container | Ports | Description |
|-----------|-------|-------------|
| `danube-broker1` | `6650`, `9040` | gRPC + Admin + Schema (`6650`), Prometheus (`9040`) |
| `danube-broker2` | `6651`, `9041` | gRPC + Admin + Schema (`6651`), Prometheus (`9041`) |
| `danube-broker3` | `6652`, `9042` | gRPC + Admin + Schema (`6652`), Prometheus (`9042`) |

Run CLI/admin commands directly via `docker exec`:

```bash
docker exec danube-broker1 danube ctl cluster status
```

To run the Web UI & HTTP MCP endpoint (`http://127.0.0.1:8080/mcp`) against your Compose cluster from the host:

```bash
./target/release/danube ctl serve --mode all --listen-addr 0.0.0.0:8080 --broker-endpoint http://127.0.0.1:6650
```

Stop and remove Compose containers/volumes when finished:

```bash
docker compose down -v
```

## Running Tests

### Unit Tests

Run all library and binary unit tests across the workspace without starting external services (matching `.github/workflows/unit-tests.yml` and `pull-request-tests.yml`):

```bash
cargo test --workspace --lib --bins
```

### Integration Tests

Integration tests require a running 3-broker cluster. Start one with `make brokers`, run the suites, then clean up:

<Steps>
1. **Start the cluster:**

   ```bash
   make brokers
   ```

   Wait a few seconds for Raft leader election.

2. **Run broker integration tests** (serial execution avoids port/timing contention):

   ```bash
   cargo test --release -p danube-broker --tests -- --test-threads=1 --nocapture
   ```

3. **Run Raft integration tests:**

   ```bash
   cargo test -p danube-raft --tests -- --nocapture
   ```

4. **Run storage integration tests:**

   ```bash
   cargo test -p danube-persistent-storage --tests -- --nocapture
   ```

5. **Stop the cluster and clean data when done:**

   ```bash
   make brokers-clean
   ```
</Steps>

:::note
The CI workflows (`.github/workflows/unit-tests.yml` and `.github/workflows/pull-request-tests.yml`) execute these same unit, lakehouse feature-check, and integration commands on every pull request.
:::

### Workspace Test Coverage

| Crate | Scope |
|-------|-------|
| `danube-broker` | Pub/sub, intents, agentic runtime primitives, schema validation, key-shared, partitioning, reliable dispatch, zero-copy branching, security, failover, topic moves |
| `danube-admin` | `danube ctl` CLI, namespace/topic/schema/security lifecycle, GitOps `apply`, HTTP UI, and 71-tool MCP server |
| `danube-raft` | Embedded Raft metadata CRUD, watch/TTL, `/cluster/config/*`, cluster leadership |
| `danube-persistent-storage` | WAL operations, retention, tiered storage (`local`, `shared_fs`, `object_store`), topic ownership transitions |
| `danube-edge` | Zero-YAML MQTT gateway and WAL-buffered replication |
| `danube-iceberg` | Apache Iceberg table exporter (enabled via `--features lakehouse`) |
| `danube-schema` | JSON Schema, Avro, Protobuf parsing and compatibility validation |
| `danube-client` | Rust client SDK and agent runtime primitives |
| `danube-core` | Shared protocol definitions, `StreamMessage`, and attribute constants |

## Submitting a Pull Request

<Steps>
1. **Create a feature branch** from `main`:

   ```bash
   git checkout -b feature/my-change
   ```

2. **Make your changes** and commit with clear messages:

   ```bash
   git add .
   git commit -m "feat: add support for XYZ"
   ```

3. **Run unit tests and workspace lakehouse check:**

   ```bash
   cargo test --workspace --lib --bins
   cargo check --workspace --features danube-broker/lakehouse
   ```

4. **Run integration tests** against a local cluster:

   ```bash
   make brokers
   cargo test --release -p danube-broker --tests -- --test-threads=1 --nocapture
   make brokers-clean
   ```

5. **Verify release build:**

   ```bash
   cargo build --release -p danube-broker
   ```

6. **Push and open a PR:**

   ```bash
   git push origin feature/my-change
   ```

   Open a pull request at [github.com/danube-messaging/danube/pulls](https://github.com/danube-messaging/danube/pulls).
</Steps>

### What Happens on PR

On every pull request, CI runs:

1. `cargo test --workspace --lib --bins` and `cargo check --workspace --features danube-broker/lakehouse`
2. Builds `./target/release/danube` (`danube-broker`) and starts a 3-broker cluster
3. Runs integration test suites (`danube-broker`, `danube-raft`, `danube-persistent-storage`)

If any test fails, broker logs from all 3 nodes are printed for debugging.

## Reading Logs

**Native Makefile brokers:**

```bash
cat temp/broker_6650.log
tail -f temp/broker_6650.log
```

**Docker Compose:**

```bash
docker compose logs -f broker1
```

**In-Memory Ring Buffer (via `danube mcp`):**

Every broker also retains the last 5,000 structured log entries and 1 hour of telemetry samples in memory, accessible over gRPC via `GetBrokerLogs` / `GetMetricsSnapshot` through `danube mcp`.

## Project Structure

```text
danube/
├── danube-broker/              # Unified `danube` binary (`up`, `ctl`, `mcp`) & E2E tests
├── danube-admin/               # CLI (`danube ctl`), HTTP UI/MCP server, 71-tool MCP backend
├── danube-client/              # Rust client library & agent runtime primitives
├── danube-core/                # Shared types, attribute keys, and protobuf definitions
├── danube-edge/                # Zero-YAML Edge MQTT gateway library
├── danube-iceberg/             # Apache Iceberg lakehouse converter (feature: lakehouse)
├── danube-persistent-storage/  # WAL, durable segments, and cloud/shared storage backends
├── danube-raft/                # Embedded Raft consensus and dynamic `/cluster/config/*` state
├── danube-schema/              # Built-in Schema Registry logic
├── docker/                     # Consolidated 3-broker `docker-compose.yml` & README
├── Dockerfile                  # Unified `ghcr.io/danube-messaging/danube` image build
├── Makefile                    # Local multi-broker development commands
└── .github/workflows/          # Unit tests & PR integration test pipelines
```
