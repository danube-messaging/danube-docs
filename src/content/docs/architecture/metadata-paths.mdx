All cluster state in Danube is a key-value entry in the embedded Raft state machine. This page lists every key path the broker uses, grouped by area. Use it when you work on cluster internals or debug a metadata issue.

<Aside type="note">
Danube once used etcd. The key hierarchy stayed, but everything now lives in embedded Raft (openraft + redb). There is no external metadata dependency.
</Aside>

<Aside type="tip">
You rarely touch these keys directly. Cluster settings under `/cluster/config/*` are changed with `danube cluster ...` or `danube apply -f desired_state.yaml`, and `danube cluster export-config` dumps them as a recovery file.
</Aside>

## Cluster membership and placement

- **`/cluster/leader`**: current leader broker ID. The Load Manager runs only there.
- **`/cluster/register/{broker_id}`**: broker registration with `broker_url`, `connect_url`, `admin_addr` (`https://` with TLS, `http://` otherwise) and optional `prom_exporter`. Written at startup with a TTL, removed on graceful shutdown.
- **`/cluster/brokers/{broker_id}/state`**: lifecycle state `active`, `draining` or `drained`, with a reason such as `lakehouse_only` (nodes started with `--role lakehouse`), `stale_restart` or `sigterm_drain`. The Load Manager only assigns topics to `active` brokers.
- **`/cluster/brokers/{broker_id}/{namespace}/{topic}`**: topic-to-broker assignment. Each broker watches its own prefix to load and unload topics.
- **`/cluster/unassigned/{namespace}/{topic}`**: topics waiting for placement. The Load Manager watches this prefix.

## Load balancing

- **`/cluster/load/{broker_id}`**: periodic load report (`resources_usage`, `topic_list`, `topics_len`), published every `load_report_interval_seconds`.
- **`/cluster/load_balance`**: the Load Manager's computed rankings and decisions.
- **`/cluster/rebalancing_history/{timestamp}`**: one entry per automated move (topic, source, target, reason). Used for rate limiting, cooldowns and audit.

See [Load Manager](/architecture/load-manager/).

## Live cluster configuration

Brokers watch `/cluster/config/*` and hot-reconcile every change.

- **`/cluster/config/storage`**: durable storage backend (`local`, `shared_fs` or `object_store`). Set with `danube cluster storage` or `danube apply`.
- **`/cluster/config/write_buffer`**: Valkey warm write buffer (`ClusterWriteBufferSpec`). Set with `danube cluster write-buffer` or `danube apply`.
- **`/cluster/config/wal`**: WAL flush, rotation and local retention (`ClusterWalRetentionSpec`). Set with `danube cluster wal`.
- **`/cluster/config/load_manager`**: assignment strategy and rebalancing (`LoadManagerConfig`). Set with `danube cluster load-manager` or `danube apply`.
- **`/cluster/config/bootstrap`**: initial bootstrap configuration, written when the cluster is created.
- **`/cluster/config/target_voter_count`**: target number of Raft voters for voter scaling.

## Audit and security

- **`/cluster/audit/{timestamp_ms}_{seq}`**: control-plane audit events (`AuditEvent`), zero-padded keys. A bounded ring keeps the newest 1,000.
- **`/cluster/security/ca`**: cluster CA certificate and sealed private key, created with `--auth auto-tls`.
- **`/auth/roles/{role_name}`**: role definitions with their permissions (`danube auth role`).
- **`/auth/bindings/{binding_id}`**: principal-to-role bindings with `principal`, `role` and `scope` (`danube auth binding`).
- **`/auth/revoked/{subject}`**: revoked JWT subjects, checked during token authentication.

Brokers watch `/auth/` and reload the RBAC and revocation cache on every change.

## Namespaces

- **`/namespaces/{namespace}/policy`**: namespace defaults such as `max_producers_per_topic`, `max_consumers_per_topic`, `max_message_size`. `0` means unlimited.
- **`/namespaces/{namespace}/topics/{namespace}/{topic}`**: topic registry for the namespace.

## Topics

All keys below sit under `/topics/{namespace}/{topic}`.

- **`/topics/{namespace}/{topic}`**: existence marker. The value is the partition count (`0` = not partitioned).
- **`.../delivery`**: dispatch mode, `"Reliable"` or `"NonReliable"`.
- **`.../policy`**: per-topic policy overrides.
- **`.../intent`**: resolved [stream intent](/concepts/stream-intents/) settings (`ExpandedStreamSettings`) from `danube topic create --intent`.
- **`.../storage_mode`**: durable tiering override, `{ "mode": "local" | "cloud_tiered" }`. Set with `danube topic storage-mode` or `danube apply`.
- **`.../schema_subject`**: the topic's bound schema subject.
- **`.../schema_config`**: subject, `validation_policy` and `enable_payload_validation`. Set with `danube topic schema configure`.
- **`.../snapshots/{timestamp_ms}`**: subscription cursor snapshots (`CursorSnapshot`) taken before a topic is unloaded or deleted.
- **`.../producers/{producer_id}`**: active producer with `producer_name`, `access_mode`, `status`, `topic_name`.

## Subscriptions

All keys below sit under `/topics/{namespace}/{topic}/subscriptions/{subscription}`.

- **`.../{subscription}`**: subscription metadata with `consumer_id`, `consumer_name` and `subscription_type` (`0` Exclusive, `1` Shared, `2` Failover, `3` Key-Shared).
- **`.../cursor`**: consumer progress offset (`u64`). Writes are debounced and flushed about every 5 seconds.
- **`.../checkpoints`**: consumer checkpoint map (`offset -> base64`), restored on redelivery or broker restart.
- **`.../failure_policy`**: redelivery limit, ack timeout, backoff and poison policy. Set with `danube topic subscription failure-policy set`.
- **`.../dispatch_config`**: per-subscription override, currently `max_unacked_messages` (cluster default 10).

## Schema Registry

- **`/schemas/_global/next_schema_id`**: monotonic schema ID counter (`u64`).
- **`/schemas/{subject}/metadata`**: subject with version history, `compatibility_mode`, `created_at`, `latest_version`.
- **`/schemas/{subject}/compatibility`**: subject compatibility mode.
- **`/schemas/{subject}/versions/{version}`**: one schema version (definition, type, fingerprint).
- **`/schemas/_index/by_id/{schema_id}`**: reverse lookup from schema ID to subject.

See [Schema Registry Architecture](/architecture/schema-registry/).

## Persistent storage

These keys use the storage metadata prefix, `/danube` by default.

- **`/danube/storage/topics/{namespace}/{topic}/segments/{padded_start_offset}`**: durable segment descriptor (`start_offset`, `end_offset`, `size`, `object_id`, ...). Offsets are zero-padded to 20 digits so keys sort correctly.
- **`/danube/storage/topics/{namespace}/{topic}/segments/cur`**: pointer to the latest published segment.
- **`/danube/storage/topics/{namespace}/{topic}/state`**: sealed marker for topic moves (`sealed`, `last_committed_offset`, `broker_id`, `timestamp`). Written on unload, read on recovery.

See [Reliable Topic Move](/architecture/reliable-topic-move/).

## Edge

On the central cluster:

- **`/edge_registry/edges/{edge_name}`**: registered edge node (`EdgeState`): identity, active topic mappings, config version and last heartbeat.
- **`/edge/replicated/{namespace}/{topic}`**: replicated-offset marker for topics received from edge nodes.

On the edge node (its own local Raft):

- **`/edge/checkpoints/{namespace}/{topic}`**: last WAL offset replicated upstream (`u64`). The replicator resumes from here after a restart. For the topic `/edge1/sensors` the key is `/edge/checkpoints/edge1/sensors`.

See [Edge](/edge/overview/).
