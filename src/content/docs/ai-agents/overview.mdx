Agents stream tokens, hand off long tool calls, retry flaky steps and need a record of what they did. Danube gives each of those jobs the right delivery guarantees with one flag, and lets your agents operate the cluster through MCP.

## Set up an agent backbone

```bash
danube namespace create agents

danube topic create /agents/tokens    --intent realtime      # UI token stream, in memory
danube topic create /agents/events    --intent event_stream  # observations between agents
danube topic create /agents/tasks     --intent task_queue    # tool calls, retries + DLQ
danube topic create /agents/tool-log  --intent audit_log     # strict, ordered tool ledger
```

Four topics, four very different guarantees, zero tuning. See [Stream intents](/concepts/stream-intents/) for what each intent sets.

## Long tasks, leases and request/reply

The Rust client (`danube-client`) has primitives for agent workloads:

- **`extend_lease`**: keep a long tool call from being redelivered while it is still running.
- **`report_progress`**: save a checkpoint (up to 64 KiB) so the next worker resumes after a crash.
- **`cancel_task_tree`**: cancel every queued subtask under one root message.
- **`request_reply`**: send a request and wait for the correlated reply on a reply topic.

```rust
// Keep a long-running tool call alive and checkpoint it
consumer.extend_lease(&msg, 30_000).await?;
consumer.report_progress(&msg, br#"{"step":3}"#.to_vec(), 30_000).await?;

// Agent-to-tool RPC with a 10s timeout
let reply = client
    .request_reply("/agents/rpc", "/agents/rpc-replies", payload, None, Duration::from_secs(10))
    .await?;
```

More in [Consumer](/client-libraries/consumer/).

## Debug with replay

```bash
# Fork the task stream up to offset 1500 and replay it in isolation
danube topic branch /agents/tasks /agents/tasks-exp --at-offset 1500

# Rewind a subscription to the start
danube topic subscription seek /agents/events --subscription eval --to-offset 0

# Look at messages without moving any cursor
danube topic peek /agents/tasks --count 10

# Re-drive failed tasks from the DLQ after a fix
danube topic dlq replay /agents/tasks --subscription workers --max-messages 50

# Infer a JSON Schema from live traffic
danube topic schema infer /agents/events --sample-size 100
```

## Connect your agent with MCP

`danube mcp` speaks MCP over stdio, which is what IDEs expect. Point it at any broker:

```bash
danube mcp                                    # stdio, broker at http://127.0.0.1:6650
danube mcp --endpoint http://broker:6650      # a remote broker
danube mcp --http 0.0.0.0:8080                # streamable HTTP at /mcp
```

Add it to your IDE or agent config:

```json
{
  "mcpServers": {
    "danube": {
      "command": "danube",
      "args": ["mcp", "--endpoint", "http://127.0.0.1:6650"]
    }
  }
}
```

<Aside type="tip">
  Secured cluster? Add `--token`, `--tls-ca` and friends to `args`, or reuse a saved profile with `--context prod`. Destructive MCP tools require explicit confirmation and rebalancing tools support dry runs.
</Aside>
