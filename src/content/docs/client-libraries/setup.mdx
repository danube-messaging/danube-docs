Every Danube client starts with one builder call that points at a broker. This page shows how to connect locally, then how to add TLS, mTLS and JWT tokens for production.

## Connect to a local broker

<Tabs syncKey="client-lang">
<TabItem label="Rust">

```rust title="Basic connection"
use danube_client::DanubeClient;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = DanubeClient::builder()
        .service_url("http://127.0.0.1:6650")
        .build()
        .await?;

    Ok(())
}
```

</TabItem>
<TabItem label="Go">

```go title="Basic connection"
import (
    "log"

    "github.com/danube-messaging/danube-go"
)

func main() {
    client, err := danube.NewClient().ServiceURL("127.0.0.1:6650").Build()
    if err != nil {
        log.Fatalf("failed to create client: %v", err)
    }
    _ = client
}
```

</TabItem>
<TabItem label="Java">

```java title="Basic connection"
import com.danubemessaging.client.DanubeClient;

DanubeClient client = DanubeClient.builder()
        .serviceUrl("http://127.0.0.1:6650")
        .build();

// use client ...

client.close();
```

</TabItem>
<TabItem label="Python">

```python title="Basic connection"
import asyncio
from danube import DanubeClientBuilder

async def main():
    client = await (
        DanubeClientBuilder()
        .service_url("http://127.0.0.1:6650")
        .build()
    )

asyncio.run(main())
```

</TabItem>
</Tabs>

Port `6650` serves messaging, the Schema Registry and admin calls on the same endpoint, so one client connection covers everything on this section's pages. Use `http://host:port` for plain gRPC and `https://host:port` for TLS.

## Rust builder methods

- **service_url(url)**: broker endpoint. Required.
- **with_tls(ca_cert)**: verify the broker with a PEM CA file. Returns `Result`, so add `?`.
- **with_mtls(ca_cert, client_cert, client_key)**: TLS plus a client certificate. Returns `Result`.
- **with_token(token)**: send a static JWT on every request. Turns on TLS (system roots if you did not call `with_tls`).
- **with_token_supplier(fn)**: call a closure on every request to get the current JWT. Turns on TLS the same way.
- **build()**: async, returns the `DanubeClient`.

`with_api_key()` still compiles but is deprecated: use `with_token()`.

## Enable TLS

Point the client at the CA that signed the broker certificate and switch the URL to `https://`.

<Tabs syncKey="client-lang">
<TabItem label="Rust">

```rust title="TLS with a custom CA"
let client = DanubeClient::builder()
    .service_url("https://127.0.0.1:6650")
    .with_tls("./certs/ca-cert.pem")?
    .build()
    .await?;
```

</TabItem>
<TabItem label="Go">

```go title="TLS with a custom CA"
builder, err := danube.NewClient().
    ServiceURL("127.0.0.1:6650").
    WithTLS("./certs/ca-cert.pem")
if err != nil {
    log.Fatalf("failed to configure TLS: %v", err)
}

client, err := builder.Build()
```

</TabItem>
<TabItem label="Java">

```java title="TLS with a custom CA"
import java.nio.file.Path;

DanubeClient client = DanubeClient.builder()
        .serviceUrl("https://127.0.0.1:6650")
        .withTls(Path.of("./certs/ca-cert.pem"))
        .build();
```

</TabItem>
<TabItem label="Python">

```python title="TLS with a custom CA"
client = await (
    DanubeClientBuilder()
    .service_url("https://127.0.0.1:6650")
    .with_tls("./certs/ca-cert.pem")
    .build()
)
```

</TabItem>
</Tabs>

<Aside type="tip" title="Rust: rustls crypto provider">
If your binary links more than one rustls crypto backend (for example through other dependencies), rustls cannot pick one and panics at the first TLS handshake. Install one explicitly at startup: `rustls::crypto::ring::default_provider().install_default().ok();`
</Aside>

## Connect to an auto-TLS broker

`--auth auto-tls` is the fastest way to a secure broker: Danube generates its own CA, node certificate and an admin token on first boot.

<Steps>

1. Start the broker:

   ```bash
   danube up cluster --data-dir ./danube-data --single-node --auth auto-tls
   ```

2. Find the generated files in the data directory:

   - **./danube-data/tls/ca.pem**: the cluster CA. Nodes that join later get a copy of it, together with `ca-key.pem` and `jwt.secret`. See [auto-tls on a multi-node cluster](/security/tls/#auto-tls-on-a-multi-node-cluster).
   - **./danube-data/bootstrap_admin.token**: a super-admin JWT, file mode `0600`.

3. Point the client at them. The node certificate covers `localhost` and `127.0.0.1` plus the advertised address.

   ```rust title="Connect to an auto-TLS broker"
   let token = std::fs::read_to_string("./danube-data/bootstrap_admin.token")?
       .trim()
       .to_string();

   let client = DanubeClient::builder()
       .service_url("https://127.0.0.1:6650")
       .with_tls("./danube-data/tls/ca.pem")?
       .with_token(token)
       .build()
       .await?;
   ```

</Steps>

<Aside type="caution">
The bootstrap token is a super-admin credential. Use it to create roles and scoped tokens, then give applications those instead. See [Authorization](/security/authorization/).
</Aside>

## Authenticate with a JWT

When the broker runs with `--auth tls` or `--auth auto-tls`, every request needs a valid token. Get one with the `danube` CLI:

```bash
# Offline: sign a token yourself (secret must match the broker's --jwt-secret)
danube auth token create --subject my-app --jwt-secret your-secret-key

# Offline, with a shorter lifetime (default is 8760h)
danube auth token create --subject my-app --ttl 24h --jwt-secret your-secret-key

# Online: ask the cluster to issue one (needs ManageCluster)
danube auth token issue --subject agent-worker --ttl 24h

# Revoke every token for a subject, cluster-wide
danube auth token revoke --subject agent-worker
```

Then pass it to the client. Read it from the environment or a secret store, never from source code.

<Tabs syncKey="client-lang">
<TabItem label="Rust">

```rust title="JWT authentication"
let token = std::env::var("DANUBE_TOKEN")?;

let client = DanubeClient::builder()
    .service_url("https://127.0.0.1:6650")
    .with_tls("./certs/ca-cert.pem")?
    .with_token(token)
    .build()
    .await?;
```

</TabItem>
<TabItem label="Go">

```go title="JWT authentication"
token := os.Getenv("DANUBE_TOKEN")

// WithToken enables TLS with system CA roots
client, err := danube.NewClient().
    ServiceURL("127.0.0.1:6650").
    WithToken(token).
    Build()

// Or combine with a custom CA
builder, _ := danube.NewClient().
    ServiceURL("127.0.0.1:6650").
    WithTLS("./certs/ca-cert.pem")
client, _ = builder.WithToken(token).Build()
```

</TabItem>
<TabItem label="Java">

```java title="JWT authentication"
String token = System.getenv("DANUBE_TOKEN");

DanubeClient client = DanubeClient.builder()
        .serviceUrl("https://127.0.0.1:6650")
        .withTls(Path.of("./certs/ca-cert.pem")) // optional: omit to use system roots
        .withToken(token)
        .build();
```

</TabItem>
<TabItem label="Python">

```python title="JWT authentication"
import os

token = os.environ["DANUBE_TOKEN"]

client = await (
    DanubeClientBuilder()
    .service_url("https://127.0.0.1:6650")
    .with_tls("./certs/ca-cert.pem")  # optional: omit to use system roots
    .with_token(token)
    .build()
)
```

</TabItem>
</Tabs>

The client sends `Authorization: Bearer <token>` on every gRPC call. The broker checks the signature and expiry, then applies RBAC bindings.

## Rotate tokens without restarting

When tokens are refreshed underneath you (Kubernetes projected volumes, Vault agents), pass a supplier instead of a fixed token. It runs on every request, so the client always uses the newest value.

<Tabs syncKey="client-lang">
<TabItem label="Rust">

```rust title="Token rotation"
let client = DanubeClient::builder()
    .service_url("https://127.0.0.1:6650")
    .with_tls("./certs/ca-cert.pem")?
    .with_token_supplier(|| {
        std::fs::read_to_string("/var/run/secrets/danube/token")
            .unwrap_or_default()
            .trim()
            .to_string()
    })
    .build()
    .await?;
```

</TabItem>
<TabItem label="Go">

```go title="Token rotation"
client, _ := danube.NewClient().
    ServiceURL("127.0.0.1:6650").
    WithTLS("./certs/ca-cert.pem").
    WithTokenSupplier(func() string {
        data, _ := os.ReadFile("/var/run/secrets/danube/token")
        return string(data)
    }).
    Build()
```

</TabItem>
<TabItem label="Java">

```java title="Token rotation"
DanubeClient client = DanubeClient.builder()
        .serviceUrl("https://127.0.0.1:6650")
        .withTls(Path.of("./certs/ca-cert.pem"))
        .withTokenSupplier(() ->
            Files.readString(Path.of("/var/run/secrets/danube/token")).strip()
        )
        .build();
```

</TabItem>
<TabItem label="Python">

```python title="Token rotation"
def read_token():
    with open("/var/run/secrets/danube/token") as f:
        return f.read().strip()

client = await (
    DanubeClientBuilder()
    .service_url("https://127.0.0.1:6650")
    .with_tls("./certs/ca-cert.pem")
    .with_token_supplier(read_token)
    .build()
)
```
