Danube ships official clients for Rust, Go, Java and Python. They share one builder-style API, so code you write in one language reads almost the same in the others.

## Your first round trip

Start a broker (`danube up standalone`), then run this producer and consumer against `127.0.0.1:6650`:

<Tabs syncKey="client-lang">
<TabItem label="Rust">

```rust title="main.rs"
use danube_client::{DanubeClient, SubType};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = DanubeClient::builder()
        .service_url("http://127.0.0.1:6650")
        .build()
        .await?;

    // Creating the producer also creates the topic
    let mut producer = client
        .new_producer()
        .with_topic("/default/hello")
        .with_name("hello-producer")
        .build()?;
    producer.create().await?;

    // Subscribe before sending so the consumer sees the message
    let mut consumer = client
        .new_consumer()
        .with_topic("/default/hello")
        .with_consumer_name("hello-consumer")
        .with_subscription("hello-sub")
        .with_subscription_type(SubType::Exclusive)
        .build()?;
    consumer.subscribe().await?;
    let mut stream = consumer.receive().await?;

    producer.send(b"Hello Danube!".to_vec(), None).await?;

    if let Some(msg) = stream.recv().await {
        println!("got: {}", String::from_utf8_lossy(&msg.payload));
        consumer.ack(&msg).await?;
    }
    Ok(())
}
```

</TabItem>
<TabItem label="Go">

```go title="main.go"
client, _ := danube.NewClient().ServiceURL("127.0.0.1:6650").Build()
ctx := context.Background()

producer, _ := client.NewProducer().
    WithTopic("/default/hello").
    WithName("hello-producer").
    Build()
producer.Create(ctx)

consumer, _ := client.NewConsumer().
    WithTopic("/default/hello").
    WithConsumerName("hello-consumer").
    WithSubscription("hello-sub").
    WithSubscriptionType(danube.Exclusive).
    Build()
consumer.Subscribe(ctx)
stream, _ := consumer.Receive(ctx)

producer.Send(ctx, []byte("Hello Danube!"), nil)

msg := <-stream
fmt.Printf("got: %s\n", string(msg.GetPayload()))
consumer.Ack(ctx, msg)
```

</TabItem>
<TabItem label="Java">

```java title="Hello.java"
DanubeClient client = DanubeClient.builder()
        .serviceUrl("http://127.0.0.1:6650")
        .build();

Producer producer = client.newProducer()
        .withTopic("/default/hello")
        .withName("hello-producer")
        .build();
producer.create();

Consumer consumer = client.newConsumer()
        .withTopic("/default/hello")
        .withConsumerName("hello-consumer")
        .withSubscription("hello-sub")
        .withSubscriptionType(SubType.EXCLUSIVE)
        .build();
consumer.subscribe();

producer.send("Hello Danube!".getBytes(), Map.of());

// Messages arrive on consumer.receive(), a Flow.Publisher.
// See the Consumer guide for the subscriber loop.
```

</TabItem>
<TabItem label="Python">

```python title="hello.py"
import asyncio
from danube import DanubeClientBuilder, SubType

async def main():
    client = await DanubeClientBuilder().service_url("http://127.0.0.1:6650").build()

    producer = (
        client.new_producer()
        .with_topic("/default/hello")
        .with_name("hello-producer")
        .build()
    )
    await producer.create()

    consumer = (
        client.new_consumer()
        .with_topic("/default/hello")
        .with_consumer_name("hello-consumer")
        .with_subscription("hello-sub")
        .with_subscription_type(SubType.EXCLUSIVE)
        .build()
    )
    await consumer.subscribe()
    queue = await consumer.receive()

    await producer.send(b"Hello Danube!")

    msg = await queue.get()
    print(f"got: {msg.payload.decode()}")
    await consumer.ack(msg)

asyncio.run(main())
```

## Install a client

<Tabs syncKey="client-lang">
<TabItem label="Rust">

Async client built on Tokio.

```bash
cargo add danube-client
cargo add tokio --features full
```

[crates.io](https://crates.io/crates/danube-client) · [docs.rs](https://docs.rs/danube-client) · [Examples](https://github.com/danube-messaging/danube/tree/main/danube-client/examples)

</TabItem>
<TabItem label="Go">

Context-based client over gRPC.

```bash
go get github.com/danube-messaging/danube-go
```

[pkg.go.dev](https://pkg.go.dev/github.com/danube-messaging/danube-go) · [Examples](https://github.com/danube-messaging/danube-go/tree/main/examples)

</TabItem>
<TabItem label="Java">

Java 21+, virtual threads and a reactive `Flow.Publisher` API.

```groovy title="Gradle"
implementation 'com.danube-messaging:danube-client:0.4.0'
```

```xml title="Maven"
<dependency>
    <groupId>com.danube-messaging</groupId>
    <artifactId>danube-client</artifactId>
    <version>0.4.0</version>
</dependency>
```

[Examples](https://github.com/danube-messaging/danube-java/tree/main/examples)

</TabItem>
<TabItem label="Python">

Async client built on `asyncio` and `grpc.aio`.

```bash
pip install danube-client
```

[Examples](https://github.com/danube-messaging/danube-py/tree/main/examples)

</TabItem>
</Tabs>

## What every client supports

<CardGrid>
  <Card title="Producers and consumers" icon="rocket">
    Partitioned topics, reliable dispatch, routing keys and attributes.
  </Card>
  <Card title="All subscription types" icon="random">
    Exclusive, Shared, Failover and Key-Shared, with `ack` and `nack`.
  </Card>
  <Card title="Schema Registry" icon="document">
    JSON Schema, Avro and Protobuf, with version pinning.
  </Card>
  <Card title="Security" icon="approve-check">
    TLS, mTLS, JWT tokens and runtime token rotation.
  </Card>
</CardGrid>

<Aside type="note" title="Rust-only agent primitives">
The Rust client (`danube-client`) adds four primitives for long-running and AI agent workloads: `request_reply`, `extend_lease`, `report_progress` and `cancel_task_tree`. See [Danube for AI Agents](/ai-agents/overview/) for patterns.
</Aside>
