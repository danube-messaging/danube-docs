A consumer reads a topic through a named subscription. Build it, `subscribe()`, then loop over `receive()` and `ack()` each message once you have processed it.

## Receive your first messages

<Tabs syncKey="client-lang">
<TabItem label="Rust">

```rust title="Subscribe and process"
use danube_client::{DanubeClient, SubType};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = DanubeClient::builder()
        .service_url("http://127.0.0.1:6650")
        .build()
        .await?;

    let mut consumer = client
        .new_consumer()
        .with_topic("/default/my-topic")
        .with_consumer_name("my-consumer")
        .with_subscription("my-subscription")
        .with_subscription_type(SubType::Exclusive)
        .build()?;

    consumer.subscribe().await?;
    let mut stream = consumer.receive().await?;

    while let Some(message) = stream.recv().await {
        println!("received: {}", String::from_utf8_lossy(&message.payload));
        consumer.ack(&message).await?;
    }
    Ok(())
}
```

</TabItem>

<Aside type="tip">
Ack only after processing succeeds. On reliable topics, unacked messages are redelivered. A brand-new subscription on a reliable topic starts at the end of the topic, so subscribe before you start producing.
</Aside>

## Rust builder methods

Required:

- **with_topic(name)**: topic to read. For partitioned topics use the base name.
- **with_consumer_name(name)**: identifies this consumer instance.
- **with_subscription(name)**: subscription to join. Consumers with the same subscription share its cursor.

Optional:

- **with_subscription_type(SubType)**: `Exclusive`, `Shared`, `FailOver` or `KeyShared`. Defaults to `Shared`.
- **with_key_filter(glob)** / **with_key_filters(vec)**: only for `KeyShared`, see [Key-Shared](/client-libraries/key-shared/).
- **with_options(ConsumerOptions)**: retry and backoff settings.

Consumer methods:

- **subscribe()**: attach to the topic (all partitions).
- **receive()**: returns a `tokio::sync::mpsc::Receiver` that yields messages.
- **ack(&msg)**: confirm processing.
- **nack(&msg, delay_ms, reason)**: reject and ask for redelivery.
- **extend_lease**, **report_progress**, **cancel_task_tree**: agent primitives, see [below](#keep-long-tasks-alive-rust).
- **close()**: stop background tasks and health checks.

## Common tasks

### Read message fields

<Tabs syncKey="client-lang">
<TabItem label="Rust">

```rust title="Message fields"
while let Some(message) = stream.recv().await {
    println!("payload:  {}", String::from_utf8_lossy(&message.payload));
    println!("topic:    {}", message.msg_id.topic_name);
    println!("offset:   {}", message.msg_id.topic_offset);
    println!("producer: {}", message.producer_name);
    println!("key:      {:?}", message.routing_key);

    for (key, value) in &message.attributes {
        println!("  {key}: {value}");
    }
    consumer.ack(&message).await?;
}
```

Other fields: `publish_time`, `schema_id`, `schema_version`. Helpers such as `correlation_id()`, `reply_to()`, `root_msg_id()` and `checkpoint_b64()` read the standard `x-danube-*` attributes.

### Reject a message (nack)

When processing fails, `nack()` hands the message back to the broker for a later retry.

<Tabs syncKey="client-lang">
<TabItem label="Rust">

```rust title="Nack on failure"
while let Some(message) = stream.recv().await {
    match process(&message) {
        Ok(_) => consumer.ack(&message).await?,
        Err(e) => {
            consumer
                .nack(&message, Some(1000), Some(format!("processing failed: {e}")))
                .await?;
        }
    }
}
```

</TabItem>
<TabItem label="Go">

```go title="Nack on failure"
for msg := range stream {
    if err := process(msg); err != nil {
        consumer.Nack(ctx, msg, 1000, fmt.Sprintf("processing failed: %v", err))
    } else {
        consumer.Ack(ctx, msg)
    }
}
```

</TabItem>
<TabItem label="Java">

```java title="Nack on failure"
// Inside onNext(StreamMessage msg):
try {
    process(msg);
    consumer.ack(msg);
} catch (Exception e) {
    consumer.nack(msg, 1000, "processing failed: " + e.getMessage());
}
```

</TabItem>
<TabItem label="Python">

```python title="Nack on failure"
while True:
    message = await queue.get()
    try:
        process(message)
        await consumer.ack(message)
    except Exception as e:
        await consumer.nack(message, delay_ms=1000, reason=f"failed: {e}")
```

</TabItem>
</Tabs>

- **delay_ms** (optional): minimum wait before redelivery. The broker uses the larger of this and the subscription's backoff, capped at its maximum redelivery delay.
- **reason** (optional): free text, recorded in metrics and copied into the dead-letter message as `x-failure-reason`.

What happens next depends on the subscription's failure policy: retry after backoff while attempts remain, then apply the poison policy (dead-letter, drop or block). See [Dispatch Strategies](/concepts/dispatch-strategies/).

### Consume a partitioned topic

Nothing changes in your code. Use the base topic name and the client subscribes to every partition, merging them into one stream.

```rust
// /default/my-topic has partitions -part-0, -part-1, -part-2
let mut consumer = client
    .new_consumer()
    .with_topic("/default/my-topic")
    .with_consumer_name("partition-consumer")
    .with_subscription("partition-sub")
    .build()?;
```

Order is kept within each partition, not across partitions. Use a routing key if related messages must stay in order (see [Key-Shared](/client-libraries/key-shared/)).

### Consume an intent topic

Topics created with `--intent` give every subscription a retry and poison-message policy out of the box:

- **event_stream**: 3 retries, 500 ms base backoff, then the message moves to `<topic>-dlq`.
- **task_queue**: 5 retries, 1000 ms base backoff, then `<topic>-dlq`.
- **audit_log**: 10 retries, 500 ms base backoff, then delivery **blocks** on that message. No DLQ, nothing is skipped.
- **realtime**: non-reliable, no redelivery.

Dead-lettered messages carry `x-original-topic`, `x-original-subscription`, `x-original-topic-offset`, `x-failure-reason` and `x-delivery-attempt`. Inspect and recover them from the CLI:

```bash
# List the subscriptions on a topic
danube topic subscription list /default/orders

# Show the retry and DLQ policy of a subscription
danube topic subscription failure-policy get /default/orders --subscription workers

# Send dead-lettered messages back to the source topic
danube topic dlq replay /default/orders --subscription workers
```

See [Stream Intents](/concepts/stream-intents/) for the full profiles.

### Tune reconnects (Rust)

If the receive stream hits a transient error, the consumer retries with exponential backoff and resubscribes after `max_retries`. Adjust it with `ConsumerOptions`:

```rust title="Consumer retries and backoff"
use danube_client::ConsumerOptions;

let mut consumer = client
    .new_consumer()
    .with_topic("/default/orders")
    .with_consumer_name("worker-1")
    .with_subscription("workers")
    .with_subscription_type(SubType::Shared)
    .with_options(ConsumerOptions::new(5, 200, 10_000)) // retries, base ms, max ms
    .build()?;
```

### Keep long tasks alive (Rust)

Long-running workers and AI agents can hold a message past its ack timeout, save progress, and cancel related subtasks.

```rust title="Lease, checkpoint, cancel"
// Push the ack deadline 30 s further out
let lease = consumer.extend_lease(&message, 30_000).await?;
println!("extended={} deadline={}ms", lease.success, lease.new_deadline_ms);

// Save a checkpoint (max 64 KiB) and extend the lease in one call.
// If this delivery fails, the redelivered message carries it in
// message.checkpoint_b64() (attribute x-danube-checkpoint-b64).
let checkpoint = br#"{"step":3,"cursor":"page-42"}"#.to_vec();
let progress = consumer.report_progress(&message, checkpoint, 30_000).await?;
assert!(progress.accepted);

// Cancel every subtask that shares this message's x-danube-root-msg-id
if let Some(root_id) = message.root_msg_id() {
    let cancel = consumer
        .cancel_task_tree("/agents/subtasks", root_id, Some("parent cancelled".into()))
        .await?;
    println!("cancelled={} evicted_in_flight={}", cancel.cancelled, cancel.evicted_in_flight);
}
```

`cancel_task_tree` takes the topic the subtasks live on. The consumer must be subscribed to it. Patterns and attribute conventions: [Danube for AI Agents](/ai-agents/overview/).

### Shut down cleanly

```rust
consumer.close().await;
```

`close()` stops the background receive tasks and health checks for every partition.
