Danube enforces security across every data-plane, admin control-plane, and inter-broker communication channel without requiring external YAML security configuration files. Everything is configured directly through `danube up` startup flags and managed online via `danube ctl`.

## Security Modes

Start a broker with `--auth-mode` to choose the security posture:

| Mode | Client & Admin (`6650`) | Inter-Broker (`7650` & Replicator) | Certificates & JWT Secret |
| :--- | :--- | :--- | :--- |
| `none` (default) | Plain HTTP/gRPC, anonymous access | Plain TCP | None (local development only) |
| `auto-tls` | TLS + JWT Bearer auth | Mutual TLS (mTLS) | Auto-generated Cluster CA, node certs, `jwt.secret`, and `bootstrap_admin.token`; synced across Raft via `DANUBE_CLUSTER_SECRET` |
| `tls` | TLS + JWT Bearer auth | Mutual TLS (mTLS) | Operator-supplied `--tls-cert`, `--tls-key`, `--ca-cert`, and `--jwt-secret` |

<Aside type="tip">
When `--auth-mode tls` or `--auth-mode auto-tls` is enabled, **admin gRPC automatically inherits TLS (`admin_tls`)** on the single-port multiplexed `6650` listener — no separate admin port or secondary TLS toggle is needed.
</Aside>

## Defense-in-Depth Architecture

```text
Clients / danube ctl / MCP / BFF
   │
   │  gRPC over TLS (port 6650 multiplexed)
   │  Authorization: Bearer <HS256 JWT>
   ▼
┌─────────────────────────────────────────┐
│  1. TLS Termination                     │  Server TLS for clients; mTLS for brokers
├─────────────────────────────────────────┤
│  2. JWT Validation & Revocation Check   │  30s cache + instant revoked-subject check
├─────────────────────────────────────────┤
│  3. Default-Deny RBAC Engine            │  10 permissions × 5 resources (Cluster/NS/Topic)
└─────────────────────────────────────────┘
   │
   │  Mutual TLS (port 7650 Raft & Replicator)
   │  x-danube-internal-broker identity
   ▼
Other Cluster Brokers
```

## Securing HTTP Gateways (`danube ctl serve`)

When exposing the Admin UI REST BFF (`/ui/v1/...`) and Streamable HTTP MCP endpoint (`/mcp`) with `danube ctl serve --mode ui` (or `--mode all`), set `DANUBE_HTTP_TOKEN` (or `DANUBE_ADMIN_TOKEN`) and `DANUBE_HTTP_REQUIRE_AUTH=true` to require `Authorization: Bearer <token>` on all HTTP endpoints other than `/ui/v1/health`.
