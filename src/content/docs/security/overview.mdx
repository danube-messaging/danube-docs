Danube secures client traffic, admin calls and broker-to-broker links with one switch on `danube up`. There is no security config file: you pick an `--auth` mode at startup and manage tokens, roles and bindings live with `danube auth`.

## Secure a node in one command

```bash
# Generates a CA, a node certificate, a JWT secret and an admin token in the data dir
danube up standalone --data-dir ./danube-data --auth auto-tls

# Talk to it with the generated CA and admin token
danube cluster status \
  --endpoint https://127.0.0.1:6650 \
  --tls-ca ./danube-data/tls/ca.pem \
  --token "$(cat ./danube-data/bootstrap_admin.token)"
```

## Pick an auth mode

<CardGrid>
  <Card title="none" icon="laptop">
    Default. Plaintext gRPC, every caller is anonymous and allowed everything. Local development only.
  </Card>
  <Card title="auto-tls" icon="rocket">
    Danube creates the cluster CA, node certificate, JWT secret and a `bootstrap-admin` token for you. Clients use TLS + JWT, brokers use mutual TLS.
  </Card>
  <Card title="tls" icon="setting">
    Bring your own PKI with `--tls-cert`, `--tls-key` and `--ca-cert`, plus a `--jwt-secret`. Same protection as `auto-tls`.
  </Card>
</CardGrid>

With `tls` or `auto-tls`, the admin API is encrypted too. It shares port 6650 by default, and a separate `--admin-listen` address uses the same certificate.

## Three layers on every request

```text
Clients, danube CLI, MCP, console
   |  gRPC over TLS (port 6650)
   |  authorization: Bearer <HS256 JWT>
   v
 1. TLS             server TLS for clients, mutual TLS between brokers
 2. JWT             signature and expiry checked, revoked subjects rejected
 3. RBAC            default deny: a binding must grant the permission
   |
   |  mutual TLS (Raft on 7650, inter-broker replication)
   v
 Other brokers
```

## Protect the web console

`danube console` serves the console REST API (`/ui/v1/...`) and MCP over HTTP (`/mcp`). Require a bearer token on every route except `/ui/v1/health`:

```bash
danube console --require-auth --http-token "$CONSOLE_TOKEN" --endpoint https://broker1:6650 --tls-ca ./ca.pem --tls-domain broker1 --token "$ADMIN_JWT"
```

Clients send `Authorization: Bearer <token>` (or `x-api-key`). The same settings can come from `DANUBE_HTTP_REQUIRE_AUTH` and `DANUBE_HTTP_TOKEN`.

<Aside type="caution">
`--http-token` is a shared secret for the HTTP layer only. The console then calls the broker with its own `--token`, so give that JWT only the permissions the console should have.
</Aside>
