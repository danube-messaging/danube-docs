## Try Danube

Download the latest `danube` binary from the [releases page](https://github.com/danube-messaging/danube/releases) or pull the [container image](https://github.com/danube-messaging/danube/pkgs/container/danube).

<Tabs>
	<TabItem label="Standalone">
		Start a broker and test with `danube ctl`:

		```bash
		# Start the broker (Client gRPC, Schema Registry, and Admin gRPC share port 6650)
		danube up --mode standalone --data-dir ./danube-data

		# Produce messages
		danube ctl produce -s http://127.0.0.1:6650 -t /default/demo -c 10 -m "Hello, Danube!"

		# Consume messages
		danube ctl consume -s http://127.0.0.1:6650 -t /default/demo --subscription my_sub
		```

		Or run a single broker in a container:

		```bash
		docker run -p 6650:6650 -p 9040:9040 \
		  ghcr.io/danube-messaging/danube:latest \
		  up --mode standalone --data-dir /data --broker-addr 0.0.0.0:6650
		```
	</TabItem>
	<TabItem label="Cluster">
		Start a zero-YAML 3-node Raft consensus cluster directly with CLI flags:

		```bash
		danube up --mode cluster \
		  --broker-addr 0.0.0.0:6650 --raft-addr 0.0.0.0:7650 \
		  --data-dir ./danube-data \
		  --seed-nodes "node1:7650,node2:7650,node3:7650"
		```

		Or launch a local 3-broker cluster using Docker Compose:

		```bash
		git clone https://github.com/danube-messaging/danube.git
		cd danube/docker
		docker compose up -d --build
		```

		Check cluster health (defaults to `http://127.0.0.1:6650`):

		```bash
		danube ctl brokers list
		danube ctl cluster status
		```
	</TabItem>
	<TabItem label="Edge (IoT)">
		Zero-YAML MQTT gateway at the edge (`# -> /edge1/ingest` out of the box). Validates payloads, buffers into a local WAL during outages, and replicates to your central cluster over gRPC:

		```bash
		danube up --mode edge \
		  --edge-name edge1 \
		  --cloud-endpoint http://cluster:6650 \
		  --mqtt-addr 0.0.0.0:1883 \
		  --data-dir ./edge-data
		```
	</TabItem>
</Tabs>

## Why Danube?

<CardGrid stagger>
	<Card title="One Binary, Zero YAML" icon="setting">
		Run as **Standalone**, **Cluster**, **Edge**, or **Admin/MCP** all from the single `danube` binary (`danube up`, `danube ctl`, `danube mcp`) with single-port multiplexing on `6650` and no YAML files required. [Learn more →](/getting-started/broker-modes/)
	</Card>
	<Card title="Intent-Driven Pub/Sub & Queuing" icon="rocket">
		Create topics with declarative workload intents (`realtime`, `event_stream`, `task_queue`, `audit_log`) or explicit `Reliable` / `NonReliable` dispatch, WAL sync, retries, and dead-letter queues. [Learn more →](/concepts/stream-intents/)
	</Card>
	<Card title="Resilient Raft Clusters" icon="approve-check">
		Embedded Raft consensus stores cluster policies dynamically in `/cluster/config/*`, automates leader election and topic reconciliation, and balances hotspots with the load manager. [Learn more →](/getting-started/configuration-workflow/)
	</Card>
	<Card title="Cloud-Native Tiered Storage" icon="open-book">
		Local WAL for fast writes with background export to S3, GCS, Azure Blob, or shared filesystems, plus zero-copy topic branching and time-travel seeks. [Learn more →](/durability/overview/)
	</Card>
	<Card title="Schema Registry" icon="document">
		Built-in schema management with JSON Schema, Avro, and Protobuf, live schema inference (`topics infer-schema`), and backward, forward, and full compatibility enforcement. [Learn more →](/architecture/schema-registry/)
	</Card>
	<Card title="AI-Native Control Plane" icon="star">
		Operate and debug clusters via `danube mcp`: **71 tools**, **4 guided workflows** (including `explain_consumer_stall`), declarative `apply_desired_state` with `dry_run` guardrails, and built-in 1-hour telemetry and log ring buffers—no Prometheus required. [Learn more →](/admin/mcp/)
	</Card>
</CardGrid>
