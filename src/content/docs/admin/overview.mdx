Danube ships all broker, messaging, administration, and AI tooling inside **one unified binary**: `danube`. Instead of installing separate broker, messaging CLI, and admin binaries, every command shares the same gRPC client, security stack, and single-port protocol multiplexing.

## Binary Entrypoints

| Command | Purpose |
| :--- | :--- |
| `danube up` (or bare `danube`) | Start a Danube broker node (standalone or Raft cluster) |
| `danube ctl` | Admin CLI, declarative `apply`, and data-plane `produce` / `consume` |
| `danube mcp` | Start the MCP server in `stdio` mode for AI coding assistants |
| `danube ctl serve --mode ui\|mcp\|all` | Run the HTTP BFF + `/mcp` Streamable HTTP server, `stdio` MCP, or both |

## Single-Port gRPC Multiplexing

By default, Danube brokers multiplex **client data-plane gRPC and admin control-plane gRPC on port `6650`**. You do not need to open or configure a separate admin port unless you intentionally pass `--admin-addr` to `danube up` to isolate admin traffic onto a dedicated listener.

When TLS is enabled (`--auth-mode tls` or `--auth-mode auto-tls`), admin gRPC automatically shares the broker TLS configuration on the multiplexed listener.

## Getting the `danube` Binary

* **Pre-built releases**: Download the `danube` binary from the [Danube GitHub Releases](https://github.com/danube-messaging/danube/releases) page.
* **Docker**: Every Danube image bundles `/usr/local/bin/danube`, so you can run `docker exec danube-broker1 danube ctl ...` without extra containers.
* **From source**: `cargo build --release --bin danube` (add `--features danube-broker/lakehouse` if building with Iceberg lakehouse support).

Verify your installation:

```bash
danube --version
danube ctl --help
```

## Configuration & Authentication (`danube ctl`)

Control-plane subcommands (`cluster`, `brokers`, `namespaces`, `topics`, `schemas`, `security`, `apply`) accept `--endpoint` and the `DANUBE_ADMIN_*` environment variables:

| Environment Variable | Flag Equivalent | Default | Description |
| :--- | :--- | :--- | :--- |
| `DANUBE_ADMIN_ENDPOINT` | `--endpoint` (or `--broker-endpoint` on `serve`/`mcp`) | `http://127.0.0.1:6650` | Broker admin gRPC URL |
| `DANUBE_ADMIN_TLS` | `--grpc-enable-tls` (`serve`/`mcp`) | `false` | Enable TLS for admin gRPC connections |
| `DANUBE_ADMIN_CA` | `--grpc-ca` (`serve`/`mcp`) | — | CA certificate PEM path |
| `DANUBE_ADMIN_CERT` | `--grpc-cert` (`serve`/`mcp`) | — | Client certificate PEM path (for mTLS) |
| `DANUBE_ADMIN_KEY` | `--grpc-key` (`serve`/`mcp`) | — | Client private key PEM path (for mTLS) |
| `DANUBE_ADMIN_DOMAIN` | `--grpc-domain` (`serve`/`mcp`) | `localhost` | TLS SNI server name verification override |
| `DANUBE_ADMIN_TOKEN` | — | — | JWT Bearer token for admin gRPC authentication |

```bash title="Configure shell environment for a secured cluster"
export DANUBE_ADMIN_ENDPOINT=https://127.0.0.1:6650
export DANUBE_ADMIN_TLS=true
export DANUBE_ADMIN_CA=./danube-data/tls/ca.pem
export DANUBE_ADMIN_TOKEN="$(cat ./danube-data/bootstrap_admin.token)"

danube ctl brokers list
danube ctl cluster status
```

Data-plane commands (`danube ctl produce` and `danube ctl consume`) use `DANUBE_SERVICE_ADDR`, `DANUBE_TLS`, `DANUBE_CA`, `DANUBE_CERT`, `DANUBE_KEY`, and `DANUBE_TOKEN` — see [CLI: Produce & Consume](/admin/cli-messaging/).

## HTTP BFF Server (`danube ctl serve`)

`danube ctl serve` runs an Axum HTTP server (`--mode ui` or `--mode all`) exposing both the Admin UI REST BFF under `/ui/v1/...` and the Streamable HTTP MCP transport at `/mcp`:

```bash title="Start the HTTP BFF server"
danube ctl serve --mode ui \
  --listen-addr 0.0.0.0:8080 \
  --broker-endpoint http://127.0.0.1:6650 \
  --prometheus-url http://127.0.0.1:9090
```

### Common `serve` Flags

| Flag | Env Var | Default | Description |
| :--- | :--- | :--- | :--- |
| `--mode` | `DANUBE_ADMIN_MODE` | `ui` | Server mode: `ui` (HTTP BFF + `/mcp`), `mcp` (`stdio`), or `all` (both) |
| `--listen-addr` | `DANUBE_ADMIN_LISTEN_ADDR` | `0.0.0.0:8080` | HTTP bind address (`ui` and `all` modes) |
| `--broker-endpoint` | `DANUBE_ADMIN_ENDPOINT` | `http://127.0.0.1:6650` | Target broker gRPC endpoint |
| `--prometheus-url` | — | `http://localhost:9090` | Optional Prometheus URL for metrics charts |
| `--config` | `DANUBE_MCP_CONFIG` | — | Optional `mcp-config.yml` for Docker/Kubernetes log integration |
| `--cors-allow-origin` | — | — | Allowed CORS origin(s) for browser dashboards |
| `--request-timeout-ms` | — | `5000` | Upstream broker gRPC request timeout |

When `DANUBE_HTTP_TOKEN` (or `DANUBE_ADMIN_TOKEN`) is set, or `DANUBE_HTTP_REQUIRE_AUTH=true` is configured, all HTTP routes except `/ui/v1/health` require an `Authorization: Bearer <token>` header.

### Implemented HTTP Routes

| Endpoint | Method | Purpose |
| :--- | :--- | :--- |
| `/ui/v1/health` | `GET` | Health and readiness check (exempt from Bearer auth) |
| `/ui/v1/cluster` | `GET` | Cluster summary, active brokers, and Raft state |
| `/ui/v1/cluster/actions` | `POST` | Cluster/broker actions (`unload`, `activate`) |
| `/ui/v1/cluster/balance` | `GET` | Cluster load-balance score and per-broker distribution |
| `/ui/v1/cluster/rebalance` | `POST` | Trigger manual or dry-run topic rebalance |
| `/ui/v1/cluster/raft` | `GET` | Raft cluster membership and leader status |
| `/ui/v1/cluster/raft/actions` | `POST` | Raft node lifecycle (`add_node`, `promote_node`, `remove_node`) |
| `/ui/v1/brokers/{broker_id}` | `GET` | Broker details and owned topics |
| `/ui/v1/namespaces` | `GET` | Namespaces and namespace policies |
| `/ui/v1/topics` | `GET` | Cluster topic list |
| `/ui/v1/topics/{topic}` | `GET` | Topic metadata, subscriptions, producers, and consumers |
| `/ui/v1/topics/{topic}/series` | `GET` | Topic metrics time series |
| `/ui/v1/topics/actions` | `POST` | Topic operations (`create`, `delete`, `unload`, `unsubscribe`, schema config) |
| `/ui/v1/schemas` | `GET` | List registered Schema Registry subjects |
| `/ui/v1/schemas/{subject}` | `GET` | Schema subject details, versions, and compatibility |
| `/ui/v1/schemas/actions` | `POST` | Schema Registry mutations (`register`, `set_compatibility`, `delete_version`) |
| `/ui/v1/security/roles` | `GET` | List RBAC roles |
| `/ui/v1/security/roles/actions` | `POST` | Create or delete RBAC roles |
| `/ui/v1/security/bindings` | `GET` | List RBAC bindings |
| `/ui/v1/security/bindings/actions` | `POST` | Create or delete RBAC bindings |
| `/mcp` | `POST` | Streamable HTTP Model Context Protocol (MCP) endpoint |

```bash title="Example BFF API requests"
# Health check
curl http://localhost:8080/ui/v1/health

# Cluster summary & Raft state
curl http://localhost:8080/ui/v1/cluster
curl http://localhost:8080/ui/v1/cluster/balance
```
