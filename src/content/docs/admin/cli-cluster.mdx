Use `danube ctl cluster`, `danube ctl brokers`, and `danube ctl apply` to operate brokers, manage Raft consensus membership, configure cluster-wide storage and load balancing dynamically, and reconcile declarative YAML/JSON manifests.

```bash
# Default multiplexed endpoint is http://127.0.0.1:6650
export DANUBE_ADMIN_ENDPOINT=http://127.0.0.1:6650

# Or override per command
danube ctl --endpoint http://broker1:6650 brokers list
```

See [Administration Overview](/admin/overview/) for TLS and JWT environment variables (`DANUBE_ADMIN_TLS`, `DANUBE_ADMIN_CA`, `DANUBE_ADMIN_CERT`, `DANUBE_ADMIN_KEY`, `DANUBE_ADMIN_DOMAIN`, `DANUBE_ADMIN_TOKEN`).

## Brokers (`danube ctl brokers`)

### `brokers list`

List all registered brokers in the cluster, their IDs, addresses, and statuses.

```bash
danube ctl brokers list
danube ctl brokers list --output json
```

### `brokers leader-broker`

Show the current cluster controller / leader broker ID and address.

```bash
danube ctl brokers leader-broker
```

### `brokers namespaces`

List namespaces currently tracked by the cluster.

```bash
danube ctl brokers namespaces
danube ctl brokers namespaces --output json
```

### `brokers unload`

Drain topics and partitions off a broker for maintenance, upgrades, or scale-down.

```bash
danube ctl brokers unload \
  --broker-id broker-2 \
  --max-parallel 1 \
  --timeout-seconds 60
```

| Flag | Default | Description |
| :--- | :--- | :--- |
| `--broker-id <ID>` | required | Target broker ID to drain |
| `--max-parallel <N>` | `1` | Maximum concurrent topic unloads |
| `--namespaces-include <NS>` | — | Only unload topics in these namespaces (repeatable) |
| `--namespaces-exclude <NS>` | — | Skip unloading topics in these namespaces (repeatable) |
| `--dry-run` | `false` | Preview which topics would be unloaded without moving them |
| `--timeout-seconds <SEC>` | `60` | Maximum wait time for unload completion |

```bash title="Filter namespaces and dry-run"
# Preview draining only /prod, excluding /internal
danube ctl brokers unload \
  --broker-id broker-2 \
  --namespaces-include prod \
  --namespaces-exclude internal \
  --dry-run
```

### `brokers activate`

Re-activate a drained or inactive broker so the Load Manager can assign topics to it again.

```bash
danube ctl brokers activate --broker-id broker-2
danube ctl brokers activate --broker-id broker-2 --reason maintenance_complete
```

### `brokers balance`

Inspect the current cluster load-balance score and per-broker topic/partition load distribution.

```bash
danube ctl brokers balance
danube ctl brokers balance --output json
```

### `brokers rebalance`

Trigger an immediate cluster rebalance via the Load Manager.

```bash
# Preview proposed topic moves
danube ctl brokers rebalance --dry-run

# Execute up to 5 moves
danube ctl brokers rebalance --max-moves 5
```

## Cluster Consensus & Live Configuration (`danube ctl cluster`)

Raft consensus and cluster-wide storage/WAL/load-manager settings are persisted in Raft metadata — no static broker YAML edits or cluster-wide restarts are needed for runtime configuration changes. See [Cluster & Topic Configuration](/getting-started/configuration-workflow/) for workflow guidance.

### Raft Membership

```bash
# Inspect Raft leader, term, applied index, voters, and learners
danube ctl cluster status

# Add a new broker node to the Raft cluster as a learner
danube ctl cluster add-node --node-addr 10.0.1.14:7650

# Promote a learner node to a voting member
danube ctl cluster promote-node --node-id 4

# Remove a node from the Raft cluster
danube ctl cluster remove-node --node-id 4
```

<Aside type="caution">
Do not remove a voting member without confirming the remaining voters still maintain a strict quorum majority (`N/2 + 1`).
</Aside>

### `cluster storage`

View or switch the cluster-wide durable persistence storage mode (`local`, `shared-fs`, or `object-store`).

```bash
# Show active storage mode and configuration
danube ctl cluster storage status

# Switch to local node storage only
danube ctl cluster storage local --force

# Configure shared POSIX filesystem tiered storage
danube ctl cluster storage shared-fs --root /mnt/danube-shared --force

# Configure S3 / object-store tiered storage with backend key-value options
danube ctl cluster storage object-store \
  --backend s3 \
  --root s3://my-danube-bucket/segments \
  --option region=us-east-1 \
  --option endpoint=http://minio:9000 \
  --force
```

### `cluster write-buffer`

Enable or disable the distributed Raft/Etcd-backed write buffer used for sub-millisecond multi-node replication in `ha` or `dev` profiles.

```bash
# Enable HA write buffer across quorum endpoints
danube ctl cluster write-buffer enable \
  --endpoints http://10.0.1.11:2379,http://10.0.1.12:2379,http://10.0.1.13:2379 \
  --profile ha \
  --wait-replicas 2 \
  --wait-timeout-ms 250 \
  --on-wait-timeout fail \
  --max-cached-segments 64

# Disable the write buffer
danube ctl cluster write-buffer disable
```

| Flag | Default | Description |
| :--- | :--- | :--- |
| `--endpoints <URL,...>` | required | Comma-separated write-buffer endpoints |
| `--profile <ha\|dev>` | — | Preset durability profile |
| `--wait-replicas <N>` | — | Number of replicas required before acknowledging |
| `--wait-timeout-ms <MS>` | — | Replication acknowledgment timeout in milliseconds |
| `--on-wait-timeout <fail\|ack>` | — | Behavior when `--wait-timeout-ms` expires |
| `--max-cached-segments <N>` | — | Maximum cached segments in buffer |

### `cluster wal`

Tune cluster-wide Write-Ahead Log (WAL) rotation, flush batching, cache capacity, and retention thresholds.

```bash
danube ctl cluster wal \
  --retention-time-minutes 1440 \
  --retention-size-mb 10240 \
  --check-interval-minutes 5 \
  --rotate-max-bytes 134217728 \
  --rotate-max-hours 24 \
  --cache-capacity 1024 \
  --flush-interval-ms 100 \
  --flush-max-batch-bytes 1048576

# Clear WAL retention limits
danube ctl cluster wal --clear-retention
```

### `cluster load-manager`

Configure automated topic placement and rebalancing behavior across the cluster.

```bash
danube ctl cluster load-manager \
  --assignment-strategy weighted_load \
  --load-report-interval-seconds 10 \
  --rebalance true \
  --profile balanced \
  --check-interval-seconds 30 \
  --max-moves-per-hour 10 \
  --cooldown-seconds 300 \
  --min-brokers 2 \
  --min-topic-age-seconds 60 \
  --blacklist-topics /default/pinned-topic \
  --replace-blacklist
```

| Flag | Values / Type | Description |
| :--- | :--- | :--- |
| `--assignment-strategy` | `fair`, `balanced`, `weighted_load` | Strategy used for new topic placement |
| `--load-report-interval-seconds` | integer | Broker load report frequency |
| `--rebalance` | `true`, `false` | Enable or pause automatic rebalancing |
| `--profile` | `conservative`, `balanced`, `aggressive` | Rebalancing aggressiveness preset |
| `--check-interval-seconds` | integer | Interval between rebalance evaluations |
| `--max-moves-per-hour` | integer | Rate limit on automated topic moves |
| `--cooldown-seconds` | integer | Post-move cooldown period |
| `--min-brokers` | integer | Minimum brokers required before auto-rebalancing |
| `--min-topic-age-seconds` | integer | Minimum age before a topic can be moved |
| `--blacklist-topics` | topic list | Topics excluded from automated rebalancing |
| `--replace-blacklist` | flag | Replace existing blacklist instead of appending |

### `cluster export-config`

Export the active Raft-persisted cluster configuration (or a specific broker's effective view) to `yaml` or `json`.

```bash
# Print YAML cluster config to stdout
danube ctl cluster export-config --format yaml

# Export a specific broker's view to JSON
danube ctl cluster export-config \
  --broker-id broker-1 \
  --format json \
  --output ./cluster-backup.json
```

## Declarative Desired State (`danube ctl apply`)

Apply a declarative YAML or JSON manifest describing namespaces, topics, storage backends, write buffer, and load-manager settings.

```bash
# Preview planned creates, updates, and deletions without modifying the cluster
danube ctl apply -f cluster-state.yaml --dry-run

# Apply additions/updates (additive by default)
danube ctl apply -f cluster-state.yaml

# Also delete namespaces/topics missing from the manifest
danube ctl apply -f cluster-state.yaml --prune

# Force destructive storage changes when required
danube ctl apply -f cluster-state.yaml --force

# Read manifest from stdin
danube ctl apply -f - < cluster-state.yaml
```

### Example Manifest (`cluster-state.yaml`)

```yaml
namespaces:
  - payments
  - agents

topics:
  - name: /payments/transactions
    intent: audit_log
    partitions: 4
    schema_subject: payment-txn

  - name: /agents/tasks
    intent: task_queue
    partitions: 8

object_store:
  backend: s3
  root: s3://danube-prod/segments
  options:
    region: us-east-1
  force: false
```

<Aside type="tip">
Always run `danube ctl apply -f cluster-state.yaml --dry-run` before using `--prune`, since `--prune` deletes resources present in the cluster that are omitted from the manifest.
</Aside>
