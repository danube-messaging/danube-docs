The lakehouse runtime reads one YAML file, named by the `DANUBE_LAKEHOUSE_CONFIG` environment variable. This page lists every key, its default and a working example.

```bash
DANUBE_LAKEHOUSE_CONFIG=./lakehouse.yaml \
  danube up cluster --data-dir /var/lib/danube --single-node
```

A minimal file needs `broker`, `storage` and at least one entry in `topics`. Everything else has defaults. The node refuses to start if the file cannot be parsed or lists no topics.

## Complete example

```yaml title="lakehouse.yaml"
# Any broker of the cluster: segment discovery and schema lookups
broker:
  address: "localhost:6650"

# Where sealed segments are read and Parquet files are written
storage:
  backend: "s3"
  root: "s3://my-bucket/danube"
  output_prefix: "iceberg"
  options:
    endpoint: "http://minio:9000"
    region: "us-east-1"
    access_key: "minioadmin"
    secret_key: "minioadmin"

# Iceberg catalog that tracks the tables
catalog:
  type: "rest"
  name: "danube_catalog"
  properties:
    uri: "http://nessie:19120/iceberg"
    warehouse: "s3://my-bucket/warehouse"

# Global Parquet flush thresholds
compaction:
  target_parquet_size_mb: 200
  max_flush_interval_seconds: 300

# One Danube topic per Iceberg table
topics:
  - namespace: "default"
    topic: "sensor-data"
    table_name: "sensor_data"
  - namespace: "default"
    topic: "events"
    table_name: "events"
    compaction:
      target_parquet_size_mb: 100
      max_flush_interval_seconds: 60

# How often to look for new sealed segments
polling:
  interval_seconds: 30
```

## broker

- **`broker.address`** (required): `host:port` of any broker, without a scheme, for example `broker-0:6650`. Used to discover sealed segments and to resolve schemas from the registry.

## storage

The object store holding the cluster's sealed segments. Parquet files and checkpoints are written here too.

- **`storage.backend`** (required): `s3`, `gcs`, `azure` or `fs`.
- **`storage.root`** (required): bucket or path, for example `s3://my-bucket/danube` or `/mnt/danube`. Use the same root as `danube cluster storage object-store --root`.
- **`storage.output_prefix`** (default `iceberg`): prefix for checkpoint files, stored at `<output_prefix>/checkpoints/<namespace>/<topic>.json`.
- **`storage.options`** (default empty): backend options, listed below.

<Tabs>
  <TabItem label="S3 / MinIO">
    - **`endpoint`**: S3-compatible endpoint, required for MinIO.
    - **`region`**: AWS region, for example `us-east-1`.
    - **`access_key`**: access key id.
    - **`secret_key`**: secret access key.
    - **`virtual_host_style`**: `true` to use virtual-hosted bucket URLs.
  </TabItem>
  <TabItem label="GCS">
    - **`credential_file`**: path to a service account JSON key.
    - **`endpoint`**: custom endpoint, for example an emulator.
  </TabItem>
  <TabItem label="Azure">
    - **`account_name`**: storage account name.
    - **`account_key`**: storage account key.
    - **`endpoint`**: custom endpoint, for example Azurite.

    The container comes from `root`, for example `azure://my-container/danube`.
  </TabItem>
  <TabItem label="Local filesystem">
    No options. `root` is a local directory (an optional `file://` prefix is stripped). Useful for tests and single-node setups.
  </TabItem>
</Tabs>

## catalog

Leave the section out, or set `type: "none"`, to write Parquet files without a catalog.

- **`catalog.type`** (default `none`): `rest`, `glue`, `s3tables` or `none`.
- **`catalog.name`** (default `danube_catalog`): catalog identifier.
- **`catalog.properties`** (default empty): passed as-is to the catalog client.

<Tabs>
  <TabItem label="REST">
    ```yaml
    catalog:
      type: "rest"
      name: "danube_catalog"
      properties:
        uri: "http://nessie:19120/iceberg"
        warehouse: "s3://my-bucket/warehouse"
    ```

    - **`uri`**: REST catalog endpoint.
    - **`warehouse`**: warehouse name or location.

    Works with Polaris, Nessie, Unity Catalog, Snowflake Open Catalog and other Iceberg REST catalogs. Included in every `lakehouse` build.
  </TabItem>
  <TabItem label="AWS Glue">
    ```yaml
    catalog:
      type: "glue"
      name: "glue_catalog"
      properties:
        warehouse: "s3://my-datalake/warehouse"
    ```

    - **`warehouse`**: S3 location for table data.

    Uses the standard AWS credential chain (IAM role, environment, `~/.aws/credentials`). Requires the `lakehouse-aws` build.
  </TabItem>
  <TabItem label="S3 Tables">
    ```yaml
    catalog:
      type: "s3tables"
      name: "s3tables_catalog"
      properties:
        table_bucket_arn: "arn:aws:s3tables:us-east-1:123456789012:bucket/my-table-bucket"
    ```

    - **`table_bucket_arn`**: ARN of the S3 Tables bucket.

    Requires the `lakehouse-aws` build.
  </TabItem>
</Tabs>

## topics

Only listed topics are exported. Each entry maps one Danube topic to one Iceberg table.

- **`namespace`** (required): Danube namespace.
- **`topic`** (required): topic name. Together they form `/<namespace>/<topic>`.
- **`table_name`** (required): Iceberg table name. The table is created if it does not exist.
- **`compaction`**: per-topic override of the global `compaction` block.

## compaction

When to flush buffered records into a Parquet file. Whichever threshold is reached first wins.

- **`target_parquet_size_mb`** (default `200`): flush when the buffer reaches this size.
- **`max_flush_interval_seconds`** (default `300`): flush at least this often.

<Aside type="tip">
  For demos, use `1` MB and `30` seconds to see data quickly. Keep the defaults in production for well-sized Parquet files.
</Aside>

## polling

- **`interval_seconds`** (default `30`): seconds between checks for new sealed segments. Lower means fresher tables, higher means fewer calls to the broker.

## Run it in Docker

The Docker image is built with the `lakehouse` feature, so the same image runs brokers and lakehouse workers.

```bash
docker build -t danube -f Dockerfile .

docker run -d \
  -e DANUBE_LAKEHOUSE_CONFIG=/etc/danube/lakehouse.yaml \
  -v ./lakehouse.yaml:/etc/danube/lakehouse.yaml:ro \
  -p 50051:50051 \
  danube up cluster \
  --data-dir /danube-data \
  --listen 0.0.0.0:6650 \
  --admin-listen 0.0.0.0:50051 \
  --role lakehouse \
  --join
```

Then add the worker to the cluster with `danube cluster node add --node-addr http://<worker-host>:50051`.

## Environment variables

- **`DANUBE_LAKEHOUSE_CONFIG`**: path to this file. On `--role all` or `--role lakehouse` it starts the runtime; when unset, the runtime stays idle. Ignored with `--role broker`.
- **`RUST_LOG`**: log levels. Add `danube_iceberg=info` (or `debug` while troubleshooting).
