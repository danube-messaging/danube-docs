This is the lookup page: every startup flag, connection flag, environment variable and cluster setting in one place. Danube has no broker config file, so this page is the whole configuration surface.

```bash
# See exactly what a node would run with, without starting it
danube up cluster --data-dir /var/lib/danube --seed-nodes n1:7650,n2:7650 --dry-run
```

## danube up

```bash
danube up standalone [OPTIONS]
danube up cluster --data-dir <DIR> [OPTIONS]
danube up edge --data-dir <DIR> --name <NAME> --cloud-endpoint <URL> [OPTIONS]
```

The flags below are shared by all three modes. Mode-specific flags follow.

### Node

- **`--data-dir <DIR>`**: data directory holding the Raft log, node identity and WAL. Default `./danube-data` in standalone, required in cluster and edge. Env: `DANUBE_DATA_DIR`.
- **`--wal-dir <DIR>`**: put the write-ahead log on another disk. Default `<data-dir>/wal`.
- **`--role <ROLE>`**: workloads this node runs. `broker` (producers and consumers only), `lakehouse` (Iceberg conversion only) or `all`. Default `all`.

### Network

- **`--listen <ADDR>`**: client and admin gRPC listen address. Default `127.0.0.1:6650`. Env: `DANUBE_LISTEN`.
- **`--admin-listen <ADDR>`**: serve admin gRPC on a separate address. Default: shared with `--listen`.
- **`--metrics-listen <ADDR>`**: Prometheus exporter listen address. Disabled when unset.
- **`--advertised-addr <HOST:PORT>`**: address clients and peers use to reach this node, for example a Kubernetes pod DNS name. Default: derived from `--listen`. Env: `DANUBE_ADVERTISED_ADDR`.
- **`--connect-url <URL>`**: external proxy or ingress URL handed to clients.
- **`--raft-port <PORT>`**: Raft transport port. Default `7650`.

<Aside type="note">
One port, `6650`, serves client gRPC, the schema registry and admin gRPC together. Use `--admin-listen` only if you want admin traffic on its own listener.
</Aside>

### Security

- **`--auth <MODE>`**: `none` (plaintext, default), `tls` (your own certificates) or `auto-tls` (generates a cluster CA, node certificate and bootstrap admin token in the data directory). Env: `DANUBE_AUTH`.
- **`--tls-cert <FILE>`**: server certificate (PEM). Required with `--auth tls`.
- **`--tls-key <FILE>`**: server private key (PEM). Required with `--auth tls`.
- **`--ca-cert <FILE>`**: CA certificate (PEM) used to verify peers and clients. Required with `--auth tls`.
- **`--jwt-secret <SECRET>`**: HMAC secret for signing and validating JWTs. Env: `DANUBE_JWT_SECRET`.
- **`--super-admin <SUBJECT>`**: JWT subject with super-admin rights. Repeatable or comma-separated.

### Recovery and checks

- **`--recovery-config <FILE>`**: local JSON or YAML override used when Raft quorum is lost. See [recovery file](#recovery-file).
- **`--dry-run`**: print the resolved node configuration and exit without starting.

### Standalone only

`danube up standalone` has no extra flags. It runs one node with a local single-member Raft log: no membership, leader election or load balancing. When it creates a new node in the default `./danube-data`, it prints a warning so you notice where data is going.

### Cluster only

Pick at most one membership flag:

- **`--single-node`**: bootstrap a brand-new one-node cluster.
- **`--seed-nodes <HOST:PORT,...>`**: Raft addresses of the initial members. The node with the lowest id bootstraps the cluster. Env: `DANUBE_SEED_NODES`.
- **`--join`**: start empty and wait to be added with `danube cluster node add`.

With none of them, a fresh data directory bootstraps a single-node cluster and prints a warning. A data directory that already holds Raft state always resumes its existing identity and membership, whatever flags you pass.

### Edge only

- **`--name <NAME>`**: unique name of this edge node. Required. Env: `DANUBE_EDGE_NAME`.
- **`--cloud-endpoint <URL>`**: cloud Danube cluster to replicate to, e.g. `https://danube.example.com:6650`. Required unless `--recovery-config` supplies it. Env: `DANUBE_CLOUD_ENDPOINT`.
- **`--cloud-token <TOKEN>`**: token used to authenticate to the cloud cluster. Env: `DANUBE_CLOUD_TOKEN`.
- **`--mqtt-listen <ADDR>`**: MQTT listen address. Default `0.0.0.0:1883`.

See [Danube Edge](/edge/overview/) for topic mapping and replication.

### Data directory

Every data directory records the mode that created it in `danube-node.json`. Starting it later in a different mode is refused, so a standalone directory cannot accidentally become a cluster node.

<FileTree>
- danube-data/
  - danube-node.json (mode marker)
  - raft/ (Raft log, snapshots and node id)
  - wal/ (local WAL, unless --wal-dir is set)
  - tls/ (auto-tls only: ca.pem, cert.pem, key.pem, jwt.secret)
  - bootstrap_admin.token (auto-tls only: first super-admin JWT)
  - cluster_ca.secret (auto-tls only, when DANUBE_CLUSTER_SECRET is unset)
</FileTree>

## danube mcp and danube console

Both run an admin server in front of a broker and share these backend flags:

- **`--config <FILE>`**: MCP configuration file that enables log access tools. Env: `DANUBE_MCP_CONFIG`.
- **`--prometheus-url <URL>`**: Prometheus for metrics. Default `http://localhost:9090`. Env: `DANUBE_PROMETHEUS_URL`.
- **`--metrics-timeout-ms <MS>`**: Prometheus query timeout. Default `5000`.
- **`--request-timeout-ms <MS>`**: admin API request timeout. Default `5000`.

`danube mcp` adds:

- **`--http <ADDR>`**: serve streamable HTTP MCP at `/mcp` instead of stdio.

`danube console` adds:

- **`--listen <ADDR>`**: HTTP listen address. Default `0.0.0.0:8080`. Env: `DANUBE_CONSOLE_LISTEN`.
- **`--require-auth`**: require a bearer token on HTTP requests. Env: `DANUBE_HTTP_REQUIRE_AUTH`.
- **`--http-token <TOKEN>`**: bearer token accepted on HTTP requests. Env: `DANUBE_HTTP_TOKEN`.
- **`--cors-allow-origin <ORIGIN>`**: CORS allowed origin.
- **`--cache-ttl-ms <MS>`**: response cache TTL. Default `3000`.

Guides: [AI Admin (MCP)](/admin/mcp/) and [Web Console](/admin/admin-ui/).

## Client connection flags

Every command that talks to a broker (`produce`, `consume`, `topic`, `namespace`, `schema`, `cluster`, `broker`, `auth`, `apply`, `mcp`, `console`) accepts:

- **`--endpoint <URL>`**: broker endpoint. Default `http://127.0.0.1:6650`. Env: `DANUBE_ENDPOINT`.
- **`--context <NAME>`**: saved connection profile to use. Env: `DANUBE_CONTEXT`.
- **`--token <JWT>`**: JWT bearer token. Env: `DANUBE_TOKEN`.
- **`--tls`**: connect with TLS. Implied by `https://` endpoints. Env: `DANUBE_TLS`.
- **`--tls-ca <FILE>`**: CA certificate (PEM) used to verify the broker. Env: `DANUBE_TLS_CA`.
- **`--tls-cert <FILE>`**: client certificate (PEM) for mTLS. Env: `DANUBE_TLS_CERT`.
- **`--tls-key <FILE>`**: client private key (PEM) for mTLS. Env: `DANUBE_TLS_KEY`.
- **`--tls-domain <NAME>`**: TLS server name to verify. Default `localhost`. Env: `DANUBE_TLS_DOMAIN`.

Each setting resolves as **flag, then environment variable, then the current context, then the default**.

### Contexts

```bash
danube context add prod --endpoint https://danube.example.com:6650 \
  --tls-ca ./ca.pem --token "$TOKEN" --use
danube context list
danube context use prod
danube context show
```

- Stored client-side in `$DANUBE_CONFIG_DIR/contexts.toml`, else `$XDG_CONFIG_HOME/danube/contexts.toml`, else `~/.config/danube/contexts.toml`. The broker never reads it.
- `context add` accepts `--endpoint` (required), `--token`, `--tls`, `--tls-ca`, `--tls-cert`, `--tls-key`, `--tls-domain`, `--use` and `--force` (replace an existing profile).
- Tokens are stored in plain text; the file is created with mode `0600`.

More in [The Danube CLI](/getting-started/the-danube-cli/).

## Environment variables

### Node (danube up)

- `DANUBE_DATA_DIR`: `--data-dir`
- `DANUBE_LISTEN`: `--listen`
- `DANUBE_ADVERTISED_ADDR`: `--advertised-addr`
- `DANUBE_SEED_NODES`: `--seed-nodes` (cluster)
- `DANUBE_AUTH`: `--auth`
- `DANUBE_JWT_SECRET`: `--jwt-secret` (also used by `danube auth token create|validate`)
- `DANUBE_EDGE_NAME`: `--name` (edge)
- `DANUBE_CLOUD_ENDPOINT`: `--cloud-endpoint` (edge)
- `DANUBE_CLOUD_TOKEN`: `--cloud-token` (edge)
- `DANUBE_CLUSTER_SECRET`: secret protecting the auto-tls cluster CA. When unset, one is generated in `<data-dir>/cluster_ca.secret`.
- `DANUBE_LAKEHOUSE_CONFIG`: path to the lakehouse config that activates Iceberg pipelines on `lakehouse` and `all` nodes. See [Iceberg configuration](/reference/iceberg-configuration/).

### Clients

- `DANUBE_ENDPOINT`, `DANUBE_CONTEXT`, `DANUBE_TOKEN`
- `DANUBE_TLS`, `DANUBE_TLS_CA`, `DANUBE_TLS_CERT`, `DANUBE_TLS_KEY`, `DANUBE_TLS_DOMAIN`
- `DANUBE_CONFIG_DIR`: where `contexts.toml` lives.

### Console and MCP

- `DANUBE_CONSOLE_LISTEN`, `DANUBE_HTTP_REQUIRE_AUTH`, `DANUBE_HTTP_TOKEN` (console)
- `DANUBE_MCP_CONFIG`, `DANUBE_PROMETHEUS_URL` (console and mcp)

### Logging

- `RUST_LOG`: log filter for every command. Node default: `warn,danube_broker=info,danube_raft=info,danube_persistent_storage=info,danube_client=info`. Logs go to stderr.

## Cluster-wide settings

These are not startup flags. They live in Raft, apply to every broker, and change live without restarts. Set them imperatively with `danube cluster ...` or declaratively with `danube apply`.

### Storage: danube cluster storage

- **`show`**: print the effective storage configuration.
- **`local [--force]`**: local WAL only.
- **`shared-fs --root <ROOT> [--force]`**: shared filesystem (NFS, EFS) for durable segments.
- **`object-store --backend <BACKEND> --root <ROOT> [--option KEY=VALUE]... [--force]`**: object storage.
  - Backends: `s3`, `gcs`, `azblob`, `filesystem`.
  - Root: `s3://bucket/prefix`, `gcs://bucket/prefix`, `azblob://container/prefix`, or a path for `filesystem`.
  - S3 options: `region`, `endpoint`, `access_key`, `secret_key`, `session_token`, `anonymous`, `profile`, `role_arn`, `session_name`, `virtual_host_style`.
  - GCS options: `project`, `endpoint`, `credential_file`, `credentials_path`, `credentials_json`.
  - Azure options: `account_name`, `account_key`, `endpoint`.
- **`--force`**: allow the change while cloud-tiered topics exist.

### Write buffer: danube cluster write-buffer

- **`enable --endpoints <URL,...>`**: enable or update the Valkey warm write buffer.
  - `--profile <ha|dev>`: preset. `ha` = 1 replica, 100 ms, `fail`, 10 cached segments. `dev` = 0 replicas, 50 ms, `ack`, 2 cached segments.
  - `--wait-replicas <N>`: replicas that must confirm a write.
  - `--wait-timeout-ms <MS>`: how long to wait for them.
  - `--on-wait-timeout <fail|ack>`: reject or accept the write on timeout.
  - `--max-cached-segments <N>`: closed WAL segments kept in Valkey.
- **`disable`**: turn it off.

### WAL and retention: danube cluster wal

Run with no flags to print the current cluster config.

- `--retention-time-minutes <N>`: retention window.
- `--retention-size-mb <N>`: retention size cap in MiB.
- `--check-interval-minutes <N>`: how often the retention deleter runs.
- `--rotate-max-bytes <N>`: segment rotation size.
- `--rotate-max-hours <N>`: segment rotation age.
- `--cache-capacity <N>`: in-memory WAL cache, in entries.
- `--flush-interval-ms <N>`: batch flush interval.
- `--flush-max-batch-bytes <N>`: batch flush size.
- `--clear-retention`: remove retention limits and stop the background deleter.

### Load manager: danube cluster load-manager

Run with no flags to print the current settings.

- `--assignment-strategy <fair|balanced|weighted_load>`: placement of new topics.
- `--load-report-interval-seconds <N>`: how often brokers report load.
- `--rebalance <true|false>`: automated rebalancing on or off.
- `--profile <conservative|balanced|aggressive>`: preset for check interval, moves per hour and cooldown.
- `--check-interval-seconds <N>`, `--max-moves-per-hour <N>`, `--cooldown-seconds <N>`: override the preset.
- `--min-brokers <N>`: active brokers required before rebalancing.
- `--min-topic-age-seconds <N>`: topics younger than this are never moved.
- `--blacklist-topics <PATTERNS>`: comma-separated topic patterns never moved. Appends unless `--replace-blacklist` is given.
- `--replace-blacklist`: replace the list (alone, it clears it).

### Export: danube cluster export-config

- `--format <yaml|json>`: default `yaml`.
- `--output <FILE>`: write to a file instead of stdout.
- `--broker-id <ID>`: include that broker's bind and admin addresses.

Task-style examples for all of these are in [CLI: Cluster, Brokers & Access](/admin/cli-cluster/).

## Desired-state manifest

`danube apply -f <FILE> [--dry-run] [--prune] [--force]` reconciles the cluster with a YAML or JSON file (`-` reads stdin). Every section is optional.

```yaml title="desired_state.yaml"
namespaces:
  - production

topics:
  - name: /production/orders     # required
    intent: audit_log            # realtime | event_stream | task_queue | audit_log
    partitions: 6
    dispatch_strategy: reliable  # non_reliable | reliable
    schema_subject: orders-value
    storage_mode: cloud_tiered   # local | cloud_tiered

# Use shared_fs OR object_store
object_store:
  backend: s3                    # s3 | gcs | azblob | filesystem
  root: s3://my-bucket/danube
  options:
    region: us-east-1
  force: false

write_buffer:
  enabled: true
  endpoints: ["redis://valkey-0:6379", "redis://valkey-1:6379"]
  profile: ha                    # ha | dev
  wait_replicas: 1
  wait_timeout_ms: 100
  on_wait_timeout: fail          # fail | ack
  max_cached_closed_segments: 10

load_manager:
  assignment_strategy: balanced  # fair | balanced | weighted_load
  load_report_interval_seconds: 30
  rebalancing:
    enabled: false
    aggressiveness: balanced     # conservative | balanced | aggressive
    check_interval_seconds: 300
    max_moves_per_hour: 10
    cooldown_seconds: 60
    min_brokers_for_rebalance: 2
    min_topic_age_seconds: 300
    blacklist_topics: ["/system/*"]
```

- **`namespaces`**: namespaces to create. Namespaces of listed topics are created automatically.
- **`topics`**: topics to create or update. Only `name` is required.
- **`shared_fs`**: `root` and `force`.
- **`object_store`**: `backend`, `root`, `options` and `force`.
- **`write_buffer`**: same fields as `danube cluster write-buffer enable`.
- **`load_manager`**: same fields as `danube cluster load-manager`.

Apply is additive. `--prune` also deletes topics missing from the manifest (only empty, idle ones unless `--force`), and never touches `/system/*`.

## Recovery file

<Aside type="caution">
`--recovery-config` is for emergencies: lost quorum, admin lockout, a broken storage setting. On a healthy cluster always use `danube cluster ...` or `danube apply`.
</Aside>

Export one while things are healthy, and use it only to start a node in trouble:

```bash
danube cluster export-config --format yaml --output recovery.yaml
danube up cluster --data-dir /var/lib/danube --recovery-config recovery.yaml
```

Every field is optional; only fields present in the file override the node:

- **`seed_nodes`**: force the Raft seed list.
- **`super_admins`**: JWT subjects with super-admin rights, to recover from a lockout.
- **`auto_create_topics`**: allow topic creation on first publish.
- **`policies`**: default namespace limits (producers, subscriptions, consumers, rates, message size).
- **`storage`**: storage mode, durable backend, local retention, WAL and write buffer.
- **`load_manager`**: same structure as in the manifest.
- **`auth`**: auth mode, TLS files, JWT settings and super admins.
- **`broker_addr`**, **`admin_addr`**: bind address overrides.
- **`edge`**: full edge configuration with custom MQTT topic mappings. Read in edge mode, never written by `export-config`.

Walkthrough in [Crash Recovery](/durability/crash-recovery/).
